# ADR-014: Decorator-First Architecture, Service-Layer Method Aspect Weaving & Unified Entity Schema

- **Status:** Accepted
- **Date:** 2026-11-20
- **Supersedes / Relates to:** ADR-001, ADR-002, ADR-007, ADR-008, ADR-012, ADR-013

---

## Context

Prior to this decision, Bunest's NestJS-compatible enhancer pipeline (`@UseGuards`, `@UsePipes`, `@UseInterceptors`, `@UseFilters`) operated exclusively at transport entrypoints (HTTP routes, GraphQL resolvers, WebSocket gateways, and microservice handlers). Business logic inside `@Injectable()` services still required repetitive imperative boilerplate for cross-cutting concerns:

- Wrapping methods manually in `this.sqlite.transaction(async () => ...)` or `this.sql.transaction(...)`
- Writing inline SQL CRUD and finder queries inside services
- Wrapping service bodies in `this.cache.wrap(...)`, `this.tracer.startActiveSpan(...)`, `this.locks.runWithLock(...)`, `this.cls.run(...)`, or `this.events.emitAsync(...)`
- Repeating `implements BunestModule { configure(consumer) { ... } }` and multiple `APP_GUARD` providers for controller/method middleware and security wiring
- Resilience decorators (`@Retry`, `@Timeout`, `@CircuitBreaker`, `@Bulkhead`, `@Fallback`, `@Resilience`) executing only at transport entrypoints via `ResilienceInterceptor` and acting as no-ops on plain `@Injectable()` service methods

At the same time, introducing service-layer Aspect-Oriented Programming (AOP) and declarative repositories MUST preserve every core Bunest invariant:
- **Zero hot-path overhead** on undecorated classes and HTTP fast-path singleton routes (`executeFastSingletonRoute`)
- **Zero new external runtime dependencies** and **zero RxJS** (ADR-008)
- **Zero circular imports** (runtime, type-only, and cross-package DAG)
- **Full DI scope support** (`Scope.SINGLETON`, `Scope.TRANSIENT`, `Scope.REQUEST`, and `useFactory` providers) without violating fail-fast `ScopeLeakException` (ADR-012)
- **Strict SQL injection resistance** on declarative repositories

## Decision

### 1. Core Service-Layer Method Aspect Contract (`@bunest/common`)

1. **Metadata Keys & Utilities (`packages/common/src/constants/metadata-keys.ts`, `metadata-registry.ts`):**
   - Added namespaced metadata keys `METADATA_KEYS.METHOD_ASPECTS`, `METADATA_KEYS.CLASS_METHOD_ASPECTS`, `METADATA_KEYS.MIDDLEWARES`, and `METADATA_KEYS.INHERIT_METHOD_ENHANCERS`.
   - Added `MetadataRegistry.copyMetadata()`, `MetadataRegistry.getMergedMethodArray<T>()`, and `wrapMethodDescriptor()` so aspect wrapping preserves method `.name`, `.length`, `this` binding, property descriptors, and all registered metadata without mutating parent prototypes.
   - Updated `Reflector.getAllAndMerge()` to merge array and plain-object metadata cleanly across class inheritance chains without duplicating explicitly passed ancestors.

2. **Composable Decorator Factory (`packages/common/src/decorators/method-aspect.decorator.ts`):**
   - `createMethodAspectDecorator<TOptions>(token, options?, order?)` returns a `ClassDecorator & MethodDecorator` that registers copy-on-write `MethodAspectMetadata` entries.
   - Accepts three `MethodAspectToken` forms:
     1. A DI `InjectionToken` (class, string, or symbol) resolving to a `MethodAspectHandler` (`{ intercept(ctx: MethodAspectContext<TOptions>) }`)
     2. A direct `MethodAspectHandler` object instance
     3. A direct `MethodAspectFn` function `(ctx) => unknown | Promise<unknown>`
   - Provides `hasMethodAspects(target)` and `getMethodAspects(target, methodName?)`.

3. **Declarative HTTP Middleware & Inheritance Control (`packages/common/src/decorators/enhancers.decorators.ts`):**
   - Added `@UseMiddleware(...middlewares)` (`ClassDecorator & MethodDecorator`) for declarative controller/method HTTP middleware.
   - Added `@InheritMethodEnhancers(inherit = true)` (`ClassDecorator & MethodDecorator`) to control whether overridden subclass route methods inherit parent method enhancers and custom method metadata.

---

### 2. Zero-Overhead DI Method Aspect Weaver (`@bunest/core`)

1. **`MethodAspectWeaver` (`packages/core/src/aop/method-aspect-weaver.ts`) integrated into `DIContainer` (`packages/core/src/di/di-container.ts`):**
   - Uses an **O(1) `WeakMap<Function, boolean>` presence cache (`hasAspectsForClass`)**: classes with zero declared method/class aspects skip weaving entirely with zero object allocations and zero wrapper closures.
   - Decoupled from `DIContainer` through the structural `MethodAspectResolverHost` interface (`0` circular imports).
   - Weaves only decorated methods on freshly instantiated `SINGLETON`, `TRANSIENT`, `REQUEST`, and `useFactory` instances.
   - **Synchronous return preservation:** Synchronous aspects wrapping synchronous methods return values directly without wrapping them in a `Promise`.
   - **Deterministic ordering:** Stacked decorators on the same method execute **outer-to-inner in exact top-to-bottom declaration order** (class-level before method-level, base before derived, stably sorted by `order ?? 0` ascending).
   - **Deferred/lazy resolution:** Supports circular aspect references and request-scoped aspect handlers safely via lazy slot resolution (`resolveLazy`).
   - **CLS & External Context Upgrades:** Added `@WithCls(options?)` (`WithClsAspect`, wired into `ClsModule`) and updated `ExternalContextCreator` to resolve class-based parameter pipes via DI (`this.resolve(p)`), check both `proto` and `ctor` metadata via `MetadataRegistry`, run method-level pipes without param decorators, and accept `string | symbol` method keys.

---

### 3. Declarative HTTP Middleware & Subclass Enhancer Inheritance (`@bunest/http`)

1. **`@UseMiddleware(...)` Compilation (`controller-scanner.ts`, `route-compiler.ts`):**
   - Scanned at bootstrap on controller classes and route methods and compiled into the exact execution order:
     `Global Middleware -> Module Middleware -> Controller @UseMiddleware -> Method @UseMiddleware -> Guards -> Interceptors -> Pipes -> Handler`.
   - Routes without middleware remain on `executeFastSingletonRoute` with **zero hot-path overhead**.
2. **Subclass Method Enhancer Inheritance:**
   - Overridden controller methods automatically merge parent method `@UseGuards`, `@UsePipes`, `@UseInterceptors`, `@UseFilters`, `@UseMiddleware` (parent-before-child) and inherit missing custom method metadata (e.g., `@Roles`) without mutating parent metadata, unless opted out via `@InheritMethodEnhancers(false)`.

### 4. Declarative Transactions & Spring Data-Style Compiled-Once Repositories (`@bunest/sqlite`, `@bunest/sql`)

1. **Declarative `@Transactional(options?)`:**
   - **`@bunest/sqlite`:** `@Transactional` (alias `@SqliteTransactional`, aspect `SqliteTransactionalAspect`, registered/exported by `SqliteModule.forRoot()`/`forRootAsync()`/`forRootMultiple()`). Supports async methods, synchronous `{ sync: true }` (`transactionSync`, rejecting Promise returns), `mode`, `savepointName`, named `connectionName`, class-level decoration, nested `SAVEPOINT` propagation via `AsyncLocalStorage`, and all DI scopes.
   - **`@bunest/sql`:** `@Transactional` (alias `@SqlTransactional`) wired via `SqlTransactionalAspect` (`SqlModule`), `DrizzleTransactionalAspect` (`DrizzleModule`, `{ adapter: "drizzle" }`), and `PrismaTransactionalAspect` (`PrismaModule`, `{ adapter: "prisma" }`). `SqlModule.forRoot()`/`forRootAsync()` defaults `global: true` (matching `SqliteModule.forRoot()`; opt out via `{ global: false }`).

2. **Spring Data-Style Compiled-Once Declarative Repositories:**
   - **`@bunest/sqlite`:** `@SqliteRepository(entityOrOptions)` (alias `@Repository`), `abstract class JpaRepository<TEntity, TKey = number>` (alias `DeclarativeSqliteRepository`), `@Query(sql, options?)` (alias `@SqliteQuery`), `@Modifying()`, `@SqlParam(name)` (alias `@Param`), and `SqliteModule.forFeature(repositories, connectionName?)`.
   - **`@bunest/sql`:** `@SqlRepository(entityOrOptions)`, `abstract class SqlCrudRepository<TEntity, TKey = number>` (alias `DeclarativeSqlRepository`), `@SqlEntity`, `@SqlQuery(sql, options?)` (alias `@Query`), `@Modifying()`, `@SqlParam(name)` (alias `@Param`), `@InjectSqlRepository`, and `SqlModule.forFeature(repositories, connectionName?)`.
   - **Compile-Once Execution:** `forFeature()` parses base CRUD (`findById`, `findAll`, `save`, `deleteById`, `count`, `existsById`), derived query method names (`findBy*`, `findOneBy*`, `findFirst*By*`, `findTop*By*`, `findAllBy*`, `findAllOrderBy*`, `existsBy*`, `countBy*`, `deleteBy*`, `removeBy*` with `And`/`Or`, `OrderBy*Asc`/`Desc`, `Containing`/`StartsWith`/`EndsWith`, `GreaterThan`/`GreaterThanEqual`/`LessThan`/`LessThanEqual`/`Between`, `In`/`NotIn`, `IsNull`/`IsNotNull`, `IgnoreCase`, and `camelCase <-> snake_case` column mapping), and `@Query`/`@SqlQuery` templates **once at module registration time**, registering both repository tokens and direct abstract class tokens (`constructor(private readonly users: UserRepository)`) in DI.
   - **Dialect Awareness (`@bunest/sql`):** Emits dialect-correct placeholders and quoting (`$1` / `"id"` / `RETURNING *` on PostgreSQL; `?` / `` `id` `` / non-`RETURNING` `save()` fallback on MySQL/MariaDB; `?` / `"id"` / `RETURNING *` on SQLite).

### 5. Ecosystem Declarative Service & Security Decorators

All ecosystem service decorators build directly on `createMethodAspectDecorator` (or `applyDecorators` / DI property bindings) and auto-register their aspect handlers inside their owning module:

| Package | Declarative Decorators & Module Helpers | Behavior |
|---|---|---|
| `@bunest/events` | `@EmitEvent(event, options?)`, `@EventPayload(property?, ...pipes)` | Emits sync/async events on method return (never on throw); `@EventPayload` + enhancers execute via `ExternalContextCreator` (zero overhead on plain `@OnEvent` listeners); fixed stacked `@OnEvent` top-to-bottom order & module-scoped dedup |
| `@bunest/cache` | `@Cacheable`, `@CacheEvict`, `@CachePut` | Deterministic key serialization, single-flight stampede deduplication, static/dynamic tags, `condition`/`unless`, `prefix`/`allEntries`/`beforeInvocation`, write-through updates |
| `@bunest/observability` | `@Span` / `@Trace`, `@Timed`, `@Counted`, `ObservabilityModule.forRoot()` | Dual-purpose `Span` proxy preserving `new Span()`/`instanceof Span` + decorator usage, W3C `TraceContextStorage` propagation, `recordException`, Prometheus `Histogram` & invocation/`_errors_total` `Counter`s |

| `@bunest/security` | `@Auth(...roles)`, `@Protected({ roles?, guards?, policies? })`, `SecurityModule.forRoot(...)` | Composite route guards via `applyDecorators()` + one-line declarative wiring for JWT, Throttler, `APP_GUARD`, and `SecurityHeadersMiddleware` |
| `@bunest/config` | `@InjectConfig(keyOrNamespace, defaultValue?)`, `@ConfigValue(path, defaultValue?)` | Parameter/property config injection (namespaces, flat keys, dot-paths, non-colliding defaults) and live `ConfigService`-backed property getters |
| `@bunest/locks` | `@WithLock(key, { ttl?, waitTimeout?, wait?, store? })` | Distributed leased locking with dynamic argument-derived keys, named stores/prefixes, and `LocksContext` propagation across all DI scopes |

### 6. Decorator-First Architecture Pillars (Waves 1–3)

Building on the Service-Layer Method Aspect foundation, Bunest adds three complementary **Decorator-First Architecture** pillars that eliminate repetitive module wiring, duplicate DTO/SQL/OpenAPI schemas, and proxy AOP gaps while preserving 100% backward compatibility with explicit `@Module` apps:

#### Pillar 1: Self-Registering `DecoratorRegistry`, `@AutoModule` & Pre-Indexed Controllers (`@bunest/common`, `@bunest/core`, `@bunest/http`)

1. **`DecoratorRegistry` (`packages/common/src/metadata/decorator-registry.ts`):**
   - `Symbol.for`-backed singleton registry populated automatically at class-evaluation time by `@Controller`, `@Injectable`, `@Entity`, `@SqliteRepository` (`"sqlite-repository"`), and `@SqlRepository` (`"sql-repository"`).
   - Exposes `registerController`, `registerInjectable`, `registerEntity`, `register(kind, cls, meta?)`, `getControllers`, `getInjectables`, `getEntities`, `getByKind<T>`, `getTargetsByKind`, `getMeta`, `has`, `unregister`, `markInternal`, `isInternal`, `snapshot`, `restore`, and `clear(kind?)`.
   - Internal framework classes (`SqliteService`, `SqlService`, aspect handlers, etc.) are tagged via `DecoratorRegistry.markInternal()` so user auto-discovery stays clean and deterministic.
2. **Zero-Boilerplate Auto-Discovery (`@AutoModule`, `Module({ autoDiscover })`, `BunestFactory.createAuto()`):**
   - `@AutoModule(metadata?)` and `@Module({ autoDiscover: true | AutoDiscoverOptions })` instruct `ModuleScanner` to expand discovered controllers/providers from `DecoratorRegistry` (honoring `controllers`, `providers`, `include`, and `exclude` filters, skipping internal and already-declared classes, and leaving explicit `@Module` apps 100% untouched).
   - `BunestFactory.createAuto(options?: BunestCreateAutoOptions)` bootstraps an application directly from imported/decorated classes without manually declaring a root `@Module` class.
3. **Decorator-Time Pre-Indexed Controller Descriptors (`@bunest/common`, `@bunest/http`):**
   - `@Controller(...)` builds a `WeakMap`-cached `PrecompiledControllerDescriptor` / `PrecompiledRouteDescriptor` (`precompileController`, `getPrecompiledController`, `invalidateControllerCache`) that auto-invalidates whenever `MetadataRegistry.define` or `MetadataRegistry.delete` mutates the controller, ancestor, prototype, or route handler.
   - `@bunest/http`'s `scanControllers()` consumes `MetadataRegistry.getPrecompiledController(controller)` directly while preserving `@UseMiddleware`, subclass enhancer inheritance, versioning, host matching, and conflict policies.

#### Pillar 2: Unified `@Entity` Single Source of Truth (`@bunest/common`, `@bunest/sqlite`, `@bunest/sql`, `@bunest/validation`, `@bunest/swagger`)

1. **Unified Schema Decorators (`packages/common/src/decorators/entity-schema.decorators.ts`, re-exported by `@bunest/sqlite` & `@bunest/sql`):**
   - `@Entity(tableOrOptions?)`, `@PrimaryKey(options?)`, `@PrimaryGeneratedColumn(strategyOrOptions?, extra?)` (`"increment"` | `"uuid"`), `@Column(options?)` (with `design:type` auto-inference for `String`/`Number`/`Boolean`/`Date`/`Object`/`Array`/`BigInt`/`Uint8Array`, constraints `minLength`/`maxLength`/`length`/`min`/`max`/`pattern`/`enum`, defaults, nullable, unique, custom `transformer`), `@Index`, `@Unique`, `@CreateDateColumn`, `@UpdateDateColumn`, and introspectors (`getEntitySchema`, `hasEntitySchema`, `getEntityColumns`, `getEntityIndexes`).
2. **Auto-DDL & Repository Auto-Registration (`@bunest/sqlite`, `@bunest/sql`):**
   - `generateCreateTableSql(entityClass, dialect)` generates identifier-validated, dialect-accurate `CREATE TABLE IF NOT EXISTS` and `CREATE [UNIQUE] INDEX IF NOT EXISTS` statements across `"sqlite"`, `"postgres"`, and `"mysql"`/`"mariadb"`.
   - `SqliteModule.forRoot`/`forRootAsync` and `SqlModule.forRoot`/`forRootAsync` support `entities`, `autoSync: true` (`syncEntities()` on `onModuleInit()`), and `autoRegisterRepositories: true` (discovering `@SqliteRepository`/`@SqlRepository` classes from `DecoratorRegistry` with zero `forFeature()` calls).
   - `@SqliteRepository(Entity)` and `@SqlRepository(Entity)` automatically derive table name, PK column/property, `propertyName <-> columnName` mappings, dialect-aware `boolean`/`json`/`datetime`/custom `transformer` hydration & serialization, UUID PK generation, and `@CreateDateColumn`/`@UpdateDateColumn` auto-timestamps on `save()`.
3. **Automatic `@Entity` Validation (`@bunest/validation`):**
   - `validateEntity(entityClass, value, options?)` and an idempotent `ValidationPipe` hook validate `@Entity` payloads directly against `@Column`/`@PrimaryKey` constraints (`whitelist`, `forbidNonWhitelisted`, `transform`, prototype-pollution protection, inheritance), automatically skipping omitted generated PKs, defaults, nullable columns, and auto-timestamps while merging cleanly with `class-validator` and leaving Standard Schema v1 untouched.
4. **Automatic OpenAPI 3.1 Schemas & `design:returntype` Auto-Inference (`@bunest/swagger`):**
   - `SchemaExplorer` auto-generates OpenAPI 3.1 `components.schemas[Name]` from `getEntitySchema(cls)` without repeating `@ApiProperty()`, while cleanly merging explicit `@ApiProperty`/`@ApiSchema`/`@ApiHideProperty`/`class-validator` overrides.
   - `SwaggerModule.createDocument()` expands whole-entity `@Param()`/`@Query()`/`@Body()` schemas and inspects `MetadataRegistry.getReturnType(proto, methodName)` (`design:returntype`) to auto-populate default `200`/`201` `$ref` response schemas for decorated DTO/`@Entity` return types (safely ignoring `Promise`, `Object`, `Function`, `Array`, primitives, and undecorated classes).

#### Pillar 3: Proxy-Safe & Factory-Safe Method Aspect Weaving (`@bunest/core`, `@bunest/sqlite`, `@bunest/sql`)

1. **`weaveProxyMethodAspects()` & `weaveMethodExecutor()` (`packages/core/src/aop/method-aspect-weaver.ts`, `di-container.ts`):**
   - `DIContainer` pre-warms singleton aspect tokens and automatically wraps `useFactory`-produced instances and `Proxy` objects via `weaveProxyMethodAspects()` whenever `provider.token` (class or abstract class) OR `created.constructor` carries `hasMethodAspects(...)`.
   - Exports `weaveProxyMethodAspects`, `weaveMethodExecutor`, `AspectResolver` (`AspectResolverFn | AspectResolverObject`), and `collectClassAspectTokens`.
2. **Repository Proxy Metadata Preservation (`compileSqliteRepository`, `compileSqlRepository`):**
   - Bound CRUD and `@Query`/`@SqlQuery` functions copy prototype method metadata via `MetadataRegistry.copyMetadata(protoMethod, fn)` so class-level and method-level AOP decorators (`@Transactional`, `@Cacheable`, `@Span`, `@Retry`, `@WithLock`, `@EmitEvent`, custom aspects) weave seamlessly across CRUD, `@Query`, concrete, and dynamically synthesized derived methods on `JpaRepository` and `SqlCrudRepository` proxies.

## Normative Invariants

1. **Zero Undecorated Overhead:** Plain classes without method/class aspects MUST NOT be proxied, wrapped, or allocated wrapper closures during DI instantiation (`hasAspectsForClass` O(1) `WeakMap` short-circuit).
2. **No Double-Wrapping at Entrypoints:** Resilience method aspects MUST detect transport entrypoints (`@Get`/`@Post`/GraphQL/WS/RPC) and defer to `ResilienceInterceptor` so retries/timeouts/bulkheads execute exactly once.
3. **Strict SQL Identifier & Parameter Safety:** Declarative repositories and `generateCreateTableSql()` MUST validate every table, schema, ID column, custom column mapping, index name, derived property column, `@SqlParam` name, and `save()` key against `/^[A-Za-z_][A-Za-z0-9_]*$/` (`assertSafeSqlIdentifier`), bind all runtime values exclusively via parameterized placeholders (`?` / `$1..$n`), escape `LIKE` metacharacters (`!`, `%`, `_`) with `ESCAPE '!'`, compile empty `In([])`/`NotIn([])` safely to `1 = 0` / `1 = 1`, and scan `@Query` placeholders without corrupting string literals, comments, or PostgreSQL `::type` casts.
4. **Copy-on-Write Inheritance & Cache Coherency:** Applying method aspects, `@Entity`/`@Column` metadata, or `@UseMiddleware` on a subclass MUST NEVER mutate parent class metadata, and mutating controller/route metadata MUST automatically invalidate `WeakMap` precompiled controller descriptors.
5. **Preserved Hot-Path Performance:** Verified via `bun run bench` after full 53-package + Decorator-First Architecture integration (`0.00%` errors, zero hot-path regression against raw `Bun.serve()`).

## Consequences

- Services, repositories, entities, and controllers achieve Spring Boot / NestJS-grade **Decorator-First** ergonomics (`@Entity` Single Source of Truth driving SQLite/SQL `autoSync: true`, `autoRegisterRepositories: true`, `ValidationPipe`, and `SwaggerModule` + `design:returntype`; `@AutoModule` / `BunestFactory.createAuto()`; Proxy-Safe `@Transactional`/`@Span`/`@Cacheable`/`@Retry`/`@WithLock`/`@EmitEvent` on `JpaRepository`/`SqlCrudRepository`) with **zero external dependencies**, **zero RxJS**, and **zero runtime overhead on undecorated paths**.
- `apps/playground` and flagship examples (`examples/auth-jwt-sqlite`, `examples/distributed-worker`) showcase end-to-end Decorator-First entities, auto-synced/auto-registered repositories, proxy AOP, and unified observability/security modules while preserving 100% backward compatibility.
- Every custom cross-cutting concern in user or ecosystem packages can plug cleanly into `DIContainer` using a single sanctioned API (`createMethodAspectDecorator`).
