# ADR-019: Native Bun Workers Integration (`@bunest/jobs/workers`)

- **Status:** Accepted
- **Date:** 2026-11-28
- **Related:** [ADR-001](./ADR-001.md), [ADR-014](./ADR-014.md), [ADR-016](./ADR-016.md), [ADR-017](./ADR-017.md)

---

## 1. Context

Prior to this decision, Bunest's background execution layers (`@bunest/jobs/queues`, `@bunest/jobs/scheduler`, and `@bunest/workflows`) ran asynchronous work on the main event loop or across separate OS processes via Redis/SQL. CPU-bound workloads (cryptography, image/PDF/CSV processing, compression, AST/document parsing, ML/embedding pre-processing) running on the main thread could starve `Bun.serve()` request latency.

Bun `>= 1.4.5` ships a native multi-threaded Web Workers implementation (`new Worker(...)`, `postMessage` fast paths, `smol`, `preload`, `ref`/`unref`, `Bun.isMainThread`, `Blob`/`File` URLs, and `bun build --compile` multi-entrypoint worker embedding), while still marking worker termination as experimental.

---

## 2. Decision

### 2.1 Subpath Placement (`@bunest/jobs/workers`) Preserving ADR-016's 19-Package Topology

Multi-threaded Bun Worker support is delivered as a tree-shakeable ESM subpath export **`@bunest/jobs/workers`** (and re-exported from `@bunest/jobs`), rather than creating a 20th workspace package or expanding `@bunest/core`:

1. Preserves the exact **19-package, 6-domain DAG** locked in [ADR-016](./ADR-016.md).
2. Enables direct one-way integration between `@bunest/jobs/queues` (`@Processor({ name, workerFile, workerPool })` sandboxed queue processors) and `@bunest/jobs/workers` without cross-package dependencies.
3. Isolates the experimental Bun `Worker` runtime behind `@bunest/jobs/workers` (Preview / Experimental stability tier) while preserving `@bunest/core`'s Production Preview contract.

### 2.2 Pure Web/Bun Worker Globals — Zero `node:worker_threads` (`ADR-017`)

In strict compliance with [ADR-017](./ADR-017.md), `@bunest/jobs/workers` **MUST NOT** import `node:worker_threads` or any other `node:*` module:

- Worker spawning uses global `new Worker(script, options)` with `Bun.WorkerOptions` (`smol`, `ref`, `preload`, `env`, `argv`, `name`).
- Thread detection uses `Bun.isMainThread` (`isMainThread()` / `isWorkerThread()`).
- Initial configuration uses a structured `INIT` handshake frame + `env` instead of `worker_threads.setEnvironmentData`.
- Zero-copy binary transfer uses standard `Transferable[]` (`transferable(value, transfer)`).
- Inline workers use `File` + `URL.createObjectURL()` with automatic `URL.revokeObjectURL()` cleanup on `pool.close()`.

### 2.3 Bun `1.4.5` Reliability Guarantees

1. **Zero startup message drops:** `defineWorker()` and `bootstrapWorkerApplication()` MUST attach `self.onmessage` synchronously at module load time before any `await`, buffering incoming frames until `INIT` / `onInit()` / DI container bootstrap completes and emitting `READY`.
2. **Two-phase graceful shutdown:** `WorkerSlot.close()` sends a `SHUTDOWN` frame so the worker drains in-flight tasks, runs `onShutdown()` / `appContext.close()`, and exits cleanly via `self.close()` / worker-local `process.exit(0)`. Forceful `worker.terminate()` is reserved strictly as a timeout/hung-CPU fallback.
3. **Non-hanging idle pools:** `unrefWhenIdle` defaults to `true` (`worker.unref()` while idle, `worker.ref()` while executing a task) so CLI commands, tests, and graceful shutdown never hang on idle pools.
4. **Cross-thread context & observability:** `WorkerPool.run()` automatically captures ambient CLS & W3C `traceparent` via `@bunest/core`'s `ClsContextPropagator`, restores CLS inside the worker thread, and publishes `bunest:workers:dispatch` / `bunest:workers:lifecycle` events on `diagnosticsChannel` consumed by `@bunest/observability` (`OtelAutoInstrumentation` + `WorkerPoolHealthIndicator`) with zero cross-package coupling.
5. **Stable `BUNEST_E2*` error codes:** Worker runtime errors carry cataloged codes (`BUNEST_E201`–`BUNEST_E205` in `packages/core/src/errors/error-catalog.ts`) and preserve `HttpException` / `DomainException` types across thread boundaries.
6. **Multi-thread HTTP scaling (`reusePort`):** `@bunest/core/http` exposes `ListenOptions.reusePort` forwarded directly to `Bun.serve()`, paired with `BunestWorkerCluster` in `@bunest/jobs/workers` (recommended on Linux where kernel `SO_REUSEPORT` balances connections evenly).

---

## 3. Normative Invariants

1. `packages/jobs/src/workers/**` MUST have **0** external runtime dependencies and **0** `node:*` imports.
2. `packages/jobs/src/workers/**` MUST NOT import from `packages/jobs/src/queues/**` (strict one-way internal DAG: `queues -> workers`).
3. `bunest build` and `bunest build --compile` MUST discover `**/*.worker.{ts,js,mts,mjs}` (or explicit `compilerOptions.workers` / `--worker`) and include them in build entrypoints.
4. `WorkerModule` MUST drain and close all registered pools during `beforeApplicationShutdown` / `onModuleDestroy`.
