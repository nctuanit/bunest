# ADR-006: `@Controller()` Class Decorator & HTTP Method Decorators

- **Status:** Accepted
- **Date:** 2026-11-20
- **Related:** [RFC-001](../rfcs/RFC-001-controller-routing.md), [ADR-002](./ADR-002.md), [ADR-003](./ADR-003.md), [ADR-010](./ADR-010.md), [ADR-011](./ADR-011.md)

## Context

With [ADR-003](./ADR-003.md) adopting NestJS-style controllers, `@bunest/common`, `@bunest/core`, and `@bunest/http` need exact, unambiguous decorator signatures, metadata shapes, and controller scanning rules.

## Decision

### 1. `@Controller()` Class Decorator

```ts
export interface ControllerOptions {
  path?: string | string[];
  host?: string | RegExp | Array<string | RegExp>;
  scope?: Scope; // default: Scope.SINGLETON
}

export function Controller(): ClassDecorator;
export function Controller(prefix: string | string[]): ClassDecorator;
export function Controller(options: ControllerOptions): ClassDecorator;
```

- Calling `@Controller()` with no argument defaults `ControllerMetadata.path` to `"/"` (`ControllerMetadata.path` has type `string | string[]`; scanners MUST handle both `string` and `string[]`, and both `""` and `"/"` normalize to `"/"` per [RFC-001 §3](../rfcs/RFC-001-controller-routing.md)).
- Providing `string[]` (e.g., `@Controller(["/v1/users", "/v2/users"])`) registers every route method under each prefix; each resulting route is independently normalized and collision-checked.
- `host` restricts route matching to requests whose `Host` header matches (dispatched via the fallback router per [ADR-011](./ADR-011.md)).
- `scope` defaults to `Scope.SINGLETON`; `Scope.REQUEST` or `Scope.TRANSIENT` may be opted into explicitly (see [ADR-012](./ADR-012.md)).

### 2. HTTP Method Decorators

All method decorators accept `path?: string | string[]` (default `""`):
- `@Get(path?)` -> `"GET"`
- `@Post(path?)` -> `"POST"`
- `@Put(path?)` -> `"PUT"`
- `@Patch(path?)` -> `"PATCH"`
- `@Delete(path?)` -> `"DELETE"`
- `@Options(path?)` -> `"OPTIONS"`
- `@Head(path?)` -> `"HEAD"`
- `@All(path?)` -> `"ALL"` (matches all standard HTTP verbs on that path)
- `@Sse(path?)` -> `"GET"` with `isSse: true` metadata flag (sets `text/event-stream` serialization per [ADR-010](./ADR-010.md))

A single method MAY carry multiple HTTP method decorators (e.g., `@Get("v1")` and `@Get("v2")` on the same handler); metadata appends via copy-on-write per [ADR-002](./ADR-002.md).

### 3. Route Response & Enhancer Decorators

- `@HttpCode(statusCode: number)` — method decorator overriding default response status code.
- `@Header(name: string, value: string)` — repeatable method decorator; multiple `@Header()` calls accumulate in declaration order.
- `@Redirect(url?: string, statusCode = 302)` — method decorator marking a redirect route.
- `@SetMetadata<K, V>(key: K, value: V)` — class or method decorator readable via `Reflector` (method overrides class when using `getAllAndOverride`; merges when using `getAllAndMerge`).
- `@UseGuards(...guards)`, `@UsePipes(...pipes)`, `@UseInterceptors(...interceptors)`, `@UseFilters(...filters)` — applicable on controller classes and route methods (accumulating safely without mutating parent metadata).

### 4. Controller Scanner Contract (`@bunest/http` / `@bunest/core`)

At bootstrap, the Controller Scanner iterates each module's `controllers` array:
1. Verify the class has `@Controller()` metadata; if missing, throw `InvalidControllerException` immediately.
2. Walk the controller prototype chain (stopping at `Object.prototype`) to collect all decorated route methods; subclass overrides of the same method key take precedence over base methods without mutating base metadata.
3. Combine `globalPrefix` + each `controllerPrefix` + each `methodPath` using the normalization algorithm in [RFC-001](../rfcs/RFC-001-controller-routing.md).
4. Merge `design:paramtypes` with parameter decorator metadata for each `(controller, handlerKey)` and validate against duplicate parameter indices.
5. Emit immutable `RouteDefinition[]` and fail fast on any canonical route collision before `Bun.serve()` starts.

## Consequences

- **Positive:** Exact TypeScript signatures shared across `@bunest/common`, `@bunest/core`, and `@bunest/http`; clean support for multi-prefix controllers, SSE, host matching, and safe inheritance.
- **Negative:** Prototype-chain scanning adds slight bootstrap logic complexity.
- **Mitigation:** Scanning runs once at bootstrap and is covered by dedicated inheritance and collision unit tests.
