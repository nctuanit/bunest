# ADR-018: Customizable Magic Architecture

- **Status:** Accepted
- **Date:** 2026-11-23
- **Applies to:** `@bunest/core`, `@bunest/orm`, `@bunest/cli`, `apps/vscode-bunest`
- **Extends:** [ADR-002](./ADR-002.md), [ADR-007](./ADR-007.md), [ADR-014](./ADR-014.md), [ADR-017](./ADR-017.md)

---

## 1. Context

[ADR-014](./ADR-014.md) established Bunest's decorator-first runtime magic: Service-Layer AOP (`MethodAspectWeaver`), Spring Data-style compiled-once repositories (`@OrmRepository` + `CrudRepository`), Class Macros (`@Data`, `@Value`, `@Builder`, `@FieldNameConstants`, etc.), `bunest typegen` / `bunest check` / Delombok, and `@AutoModule()` auto-discovery.

As applications scale across domain teams, **closed, hardcoded framework magic** hits six concrete limitations:

1. **Fragmented `Bun.plugin` hooks & stripped TS fields:** Separate preload/build plugins (`bunestMetadataPlugin` vs `@bunest/orm/plugin`) compete on `onLoad({ filter: /\.tsx?$/ })`, and TypeScript erases definite-assignment fields (`email!: string;`) at runtime, forcing manual `fields: [...]` hints on class macros.
2. **Non-extensible Class Macros & per-class repetition:** Teams cannot author custom single-source class macros (driving runtime, `.d.ts` typegen, IDE Hover/CodeLens, and Delombok together), compose reusable macro presets (e.g. `@DomainEntity()`), or set project-wide defaults (`fluent`, `toBuilder`, `maskValue`) without repeating options on every class.
3. **Closed derived-query DSL & manual boilerplate in repositories:** Teams need domain-specific query operators (e.g. `Matches`, `JsonContains`), cross-cutting implicit scopes (`@SoftDelete`, `@TenantScoped`) with selective opt-out (`@IgnoreScope`), narrow column projections (`@Projection`), first-class offset & keyset pagination (`Page<T>`, `CursorPage<T>`), and multi-trait repository composition beyond single inheritance.
4. **Implicit AOP ordering & repetitive method decoration:** Stacking cross-cutting service decorators without semantic execution phases makes ordering fragile, raw aspect contexts lack compile-time parameter/return/async constraints, and applying an aspect to every `*Service` requires decorating every method manually.
5. **Fixed typegen targets & fixed architecture lint rules:** Teams cannot plug custom `.d.ts` generators (or generate typed registries for i18n, queues, workflows, permissions, and AI tools) or enforce custom architecture rules (such as banning direct repository injection inside `@Controller()` classes) in `bunest check` and VS Code.
6. **Unscoped `@AutoModule()` & unconditional bean registration:** Global `DecoratorRegistry` auto-discovery lacks directory-level scoping, compile-time manifest expansion for `bun build --compile`, and Spring-style conditional bean registration (`@Profile`, `@RegisterIfEnv`, `@RegisterIfMissing`).

---

## 2. Decision

Bunest adopts a **Customizable Magic Architecture** anchored on one typed project configuration (`bunest.config.ts`), single-realm `globalThis[Symbol.for("bunest:...")]` registries (so runtime, CLI, and bundle chunks share state with zero circular imports), and six composable extension contracts — preserving **0 external npm runtime dependencies**, **0 `node:*` outside the 2 kernel adapters**, and **0 circular imports** ([ADR-017](./ADR-017.md)).

### 2.1 Unified `bunest.config.ts` & Single-Pass `createBunestPlugin()` Pipeline

- `@bunest/core` exports **`defineBunestConfig(config: BunestConfig): BunestConfig`** covering `macros`, `orm`, `aop`, `typegen`, `diagnostics`, and `plugin` using structural interfaces so `@bunest/core` has zero upward dependencies on `@bunest/orm` or `@bunest/cli`.
- `@bunest/cli` provides **`loadBunestConfig(cwd)`** (native Bun dynamic `import()` of `bunest.config.{ts,mts,js,mjs}`) and **`createBunestPlugin(options)`** / **`registerBunestPlugin(options)`** / **`transformBunestSource(source, filePath, options)`**.
- `createBunestPlugin()` MUST register **one** `onLoad` pass piping `.ts`/`.tsx` source through five deterministic, individually toggleable stages (eliminating plugin `onLoad` conflicts):
  1. **`classMacros`** (default `true`): AST-scans classes decorated with built-in or configured custom macros/presets and appends `registerMacroFields(ClassName, [...])` (auto-importing from `@bunest/core`) so zero-initializer fields (`email!: string;`) work with zero manual `fields: [...]`.
  2. **`autoModuleManifest`** (default `true`): in build mode (`expandAutoModuleGlobs`), expands `@AutoModule({ scan })` via `Bun.Glob` into static `manifest: [() => import("./...")]` arrays compatible with `bun build --compile`.
  3. **`swaggerMetadata`** (default `true`): reuses `transformDtoMetadataSource` and `transformControllerMetadataSource`.
  4. **`userTransforms`**: executes ordered `{ name, filter?, transform(source, filePath) }` hooks from `options.transforms` / `bunest.config.ts`.
  5. **`ormCircularSafe`** (default `true`): transpiles via `Bun.Transpiler` (`experimentalDecorators`, `emitDecoratorMetadata`, `verbatimModuleSyntax`) and rewrites `typeof Ident === "undefined" ? Object : Ident` into TDZ-safe IIFEs without importing `@bunest/orm`.

### 2.2 Extensible Class Macros, Presets, Global Defaults & Compile-Time Field Registration

- **`defineClassMacro<TOptions>(def)` (`@bunest/core`):** Defines a single-source `CustomMacroDefinition<TOptions>` (`name`, `compose?`, `composedNames?`, `fields?`, `methods?`, `statics?`, `apply?`, `typegen?`, `delombok?`), registers it in the single-realm registry **`globalThis[Symbol.for("bunest:custom_macros:registry")]`** (`CUSTOM_MACROS_REGISTRY_SYMBOL`), and returns a decorator factory exposing `.macroDefinition` and `.macroName`.
  - Registry helpers: `registerCustomMacro`, `unregisterCustomMacro`, `getCustomMacro`, `listCustomMacros`, `clearCustomMacros`.
  - Single-source helpers: `collectCustomMacroTypegenMembers`, `collectCustomMacroDelombokBlocks`.
  - `fields` with `defaultValue` MUST initialize lazily on plain `new Class()` without wrapping or altering the class constructor, materialize eagerly in `of()`/`from()`/`builder().build()` (supporting frozen `@Value()`), and respect `readonly: true` and `@Tolerate` non-override semantics.
- **`defineMacroPreset(name, decoratorsOrFactory, composedNames?)` (`@bunest/core`):** Built on `defineClassMacro`, composes multiple decorators (static arrays auto-infer `composedNames` via internal decorator name tagging) so CLI typegen, analyzer Hover/CodeLens, and Delombok statically expand presets.
- **`registerMacroFields(target, fields)` (`@bunest/core`):** Stores AST-discovered field names on `METADATA_KEYS.CLASS_MACROS` (`explicitFields`) and re-installs already-applied field accessors and `@FieldNameConstants` regardless of whether called before or after class decorators execute.
- **Global Macro Defaults (`@bunest/core`):** `setGlobalMacroDefaults`, `getGlobalMacroDefaults`, `resetGlobalMacroDefaults`, and `resolveGlobalToStringDefaults` backed by **`globalThis[Symbol.for("bunest:macro_defaults")]`** (`GLOBAL_MACRO_DEFAULTS_SYMBOL`). All built-in macros (`@Accessors`, `@Getter`, `@Setter`, `@ToString`, `@EqualsAndHashCode`, `@Builder`, `@SuperBuilder`, `@Data`, `@Value`, `@JsonSerializable`, `@WithLogger`, `@FieldNameConstants`) MUST inherit global defaults when a per-class option is omitted, per-class options MUST always take precedence, and unset defaults MUST produce zero behavior change.

### 2.3 Customizable Declarative Repositories (`@bunest/orm`)

- **Custom Derived Query Operators:** `registerQueryOperator`, `unregisterQueryOperator`, `getRegisteredQueryOperator`, `listRegisteredQueryOperators`, `clearRegisteredQueryOperators` backed by **`globalThis[Symbol.for("bunest:orm:custom_query_operators")]`** (`ORM_CUSTOM_QUERY_OPERATORS_SYMBOL`). Derived query parsing MUST perform longest-suffix matching with dialect-aware identifier quoting and placeholder rewriting, and invalidate compiled-query caches on registry mutation.
- **Implicit Repository Scopes:**
  - Repeatable **`@RepositoryScope<TEntity>({ name, where?, beforeSave?, onDeleteById? })`** applies automatically to CRUD and derived queries across inheritance chains (derived wins on name collision) with SQL `OR`-precedence parenthesization.
  - **`@SoftDelete(options?)`** (defaults: `column: "deleted_at"`, `property: "deletedAt"`, `name: "softDelete"`) injects `<col> IS NULL` on reads/counts/exists/deletes, converts `deleteById` into a timestamped `UPDATE`, and provides `softDeleteById`, `restoreById`, and `hardDeleteById`.
  - **`@TenantScoped(options?)`** (defaults: `column: "tenant_id"`, `property: "tenantId"`, `name: "tenant"`, `required: true`) resolves tenant ID from `resolveTenant()`, `ClsService`, or `getCurrentRequestContext()`, isolates reads/deletes, and auto-populates tenant ID on `save()`/`saveMany()`.
  - **`@IgnoreScope(...scopeNames)`** and **`runWithIgnoredScopes(names, fn)`** (backed by Bunest `ContextStorage`) disable named scopes or all scopes (no arguments) for a method or async execution scope.
- **Selective Column Projection:** **`@Projection(...fields)`** compiles explicit dialect-quoted `SELECT` column lists instead of `SELECT *` and returns plain projected objects.
- **First-Class Pagination:** `Pageable`, `Page<T>`, `CursorPageable`, `CursorPage<T>`, `isPageable`, `isCursorPageable`, `createPageable`, `createCursorPageable` power `findPageBy*` (offset `LIMIT`/`OFFSET` + scoped `COUNT(*)`) and `findCursorBy*` (keyset `LIMIT + 1` with `nextCursor` / `hasMore`), as well as trailing `Pageable` / `CursorPageable` arguments on finders.
- **Composable Repository Fragments:** `defineRepositoryFragment`, `composeRepository(BaseRepo, ...fragments)`, `@UseRepositoryFragments(...)`, `withSoftDelete`, and `withCursorPagination` mix strongly-typed repository traits and scopes without single-inheritance limits.

### 2.4 Service-Layer AOP Phases, Pipelines, Typed Aspects & Declarative Pointcuts (`@bunest/core`)

- **`AspectPhase`:** Standardized semantic execution phases (`OBSERVABILITY: -500`, `RESILIENCE: -400`, `RATE_LIMIT: -350`, `LOCK: -300`, `TRANSACTION: -200`, `CACHE: -100`, `VALIDATION: -50`, `DEFAULT: 0`, `EVENT: 100`, `AUDIT: 200`), where smaller numbers execute outermost. `createMethodAspectDecorator(token, options, orderOrPhase?)` accepts either a numeric order or `{ phase?, order? }` (`phase + order` offset).
- **`defineAspectPipeline(stepsOrFactory)`:** Composes aspect decorators and/or `{ token, options?, phase?, order? }` specs into one reusable `ClassDecorator & MethodDecorator` (static or parameterized factory), preserving semantic phase ordering.
- **`createTypedAspect<TArgs, TReturn, TOptions>(config)`:** Produces a strongly-typed method decorator with typed `args`, `proceed(...)`, and optional `asyncOnly: true` compile-time enforcement requiring `Promise`-returning target methods.
- **Declarative Pointcuts (`PointcutRule`, `AopModule`, `AOP_POINTCUTS_TOKEN`):** `AopModule.forRoot({ pointcuts })` (app-wide), `AopModule.forFeature({ pointcuts })` (module-scoped), and `registerGlobalPointcuts(...)` match classes/methods by `className`, `methodName`, `excludeMethods`, `metadataKey`, and `predicate`. `DIContainer` MUST preserve its O(1) `WeakMap<Function, boolean>` zero-overhead fast-path on classes matching neither decorator aspects nor pointcuts, invalidating the cache via a monotonic pointcut version counter.

### 2.5 Extensible Typegen Plugins & Custom Architecture Diagnostic Rules (`@bunest/cli`)

- **`defineTypegenPlugin(plugin)`:** Exposes `{ name, target?, scan(ctx), emit(data, ctx) }` integrated into `BunestTypegenScanner`, `emitBunestDeclaration`, `generateBunestTypes`, and `bunest typegen`, alongside 5 built-in ecosystem plugins (`BUILTIN_TYPEGEN_PLUGINS`):
  - `i18nTypegenPlugin` (`target: "i18n"`) → `@bunest/core/i18n` `BunestI18nRegistry` (via `Bun.Glob` + `Bun.JSONC`/`Bun.YAML`/`Bun.TOML`)
  - `jobsTypegenPlugin` (`target: "jobs"`) → `@bunest/jobs` `BunestQueueRegistry`
  - `workflowsTypegenPlugin` (`target: "workflows"`) → `@bunest/workflows` `BunestWorkflowRegistry`
  - `authzTypegenPlugin` (`target: "authz"`) → `@bunest/security/authz` `BunestPermissionRegistry`
  - `aiToolsTypegenPlugin` (`target: "ai"`) → `@bunest/ai` `BunestAiToolRegistry`
- **`defineDiagnosticRule(rule)`:** Exposes `{ code, severity, description, check(ctx) }` (with optional quick-fix text edits) wired into `analyzeProjectDiagnostics`, `bunest check`, and VS Code diagnostics, plus 2 opt-in architecture rules:
  - `noRepositoryInControllerRule` (`BUNEST_ARCH001`): flags `@Controller()` classes injecting `*Repository` directly.
  - `requireGuardOnMutationsRule` (`BUNEST_ARCH002`): flags `@Post`/`@Put`/`@Patch`/`@Delete` routes missing `@UseGuards` or `@Public`.
- **Unified Static Analyzer & Delombok:** `resolveClassMacroMembers`, `buildDelombokEdit`, and `repository-query.ts` read both `bunest.config.ts` and the single-realm global registries so custom macros, presets, custom ORM operators, scopes, projections, and pagination work across CLI and VS Code.

### 2.6 Smart Scoped `@AutoModule` & Conditional Beans (`@bunest/core`)

- **`@AutoModule(metadata)`:** Extended with `scan` (native `Bun.Glob`), `exclude` (defaults: `**/*.spec.ts`, `**/*.test.ts`, `**/*.d.ts`), `cwd`, `manifest` (build-time static `() => import(...)` loaders taking precedence over runtime globbing), `filter`, and `profiles`. Scanned classes MUST be strictly scoped to the declaring module with zero global leakage; zero-arg `@AutoModule()` remains 100% backward-compatible.
- **Conditional Bean Decorators:**
  - Pass 1 (eager): **`@RegisterIf(predicate)`**, **`@RegisterIfEnv(key, matcher?)`**, **`@Profile(...profiles)`** (supporting negation like `"!test"`, resolved in precedence order `BunestCreateOptions.profiles > AutoModuleMetadata.profiles > BUNEST_PROFILES > BUNEST_PROFILE > NODE_ENV`).
  - Pass 2 (deferred): **`@RegisterIfMissing(token?)`** evaluates after unconditional/eager providers so explicit overrides always win cleanly without `DuplicateProviderException` or orphaned exports.

## 3. Consequences

### Positive

- **Zero-boilerplate DX:** One `bunest.config.ts` + one `createBunestPlugin()` eliminates manual `fields: [...]`, eliminates plugin `onLoad` conflicts, and makes `@AutoModule({ scan })` compatible with `bun build --compile`.
- **Single-source extensibility:** Custom class macros, presets, query operators, repository scopes/fragments, AOP pipelines/pointcuts, typegen plugins, and architecture rules share one canonical contract across runtime, CLI, and IDE.
- **Zero-regression performance & isolation:** O(1) `WeakMap` AOP fast-path, compiled-once SQL caching with versioned invalidation, 0 external runtime dependencies, and 0 runtime or type-only circular imports across all 19 packages.

### Trade-offs & Invariants

- Single-realm registries use `Symbol.for("bunest:...")` on `globalThis`; test suites registering custom macros, defaults, query operators, or global pointcuts SHOULD call their respective `clear*` / `reset*` helpers in `afterEach`.
- `GlobalMacroDefaults.toString` structurally accommodates `Object.prototype.toString` so omitting `toString` on plain config literals typechecks cleanly; consumers reading `toString` defaults programmatically SHOULD use `resolveGlobalToStringDefaults()`.
- Build-time `manifest` expansion for `@AutoModule({ scan })` requires `createBunestPlugin({ expandAutoModuleGlobs: true })` (auto-enabled during `Bun.build()`).
