# ADR-017: Zero External Runtime Dependencies & Bun-Native Runtime Isolation

- **Status:** Accepted (Completed — Repo-Wide)
- **Date:** 2026-11-22 (Updated 2026-11-23 — Phase 2 Repo-Wide Completion)
- **Applies to:** Entire Bunest monorepo (`packages/*`, `apps/*`, `examples/*`, `scripts/*`, `tests/*`, and Bun benchmark harnesses)
- **Extends:** [ADR-001](./ADR-001.md), [ADR-015](./ADR-015.md), [ADR-016](./ADR-016.md)

---

## 1. Context

After [ADR-015](./ADR-015.md) (Bun-native DTO validator & transformer) and [ADR-016](./ADR-016.md) (37 → 19 package consolidation), 16 of 19 Bunest packages had zero external runtime dependencies. However, four external npm runtime dependencies (`reflect-metadata`, `magic-string`, `ts-morph`, `graphql`, ~95 MB in `node_modules`) and 153 `node:*` built-in module imports across 16 Node compatibility modules still remained in framework source code.

Relying on external third-party runtimes and scattered `node:*` imports created four systemic problems:

1. **Supply-chain & cold-start footprint:** Pulling `ts-morph` (+ bundled TypeScript compiler copy), `graphql`, `magic-string`, and `reflect-metadata` inflated install size, lockfile surface, and CLI cold-start latency.
2. **Duplicate compatibility layers:** `node:path`, `node:crypto`, `node:stream`, `node:net`, `node:tls`, `node:http`, `node:assert/strict`, `node:diagnostics_channel`, `node:os`, `node:util`, `node:url`, `node:module`, and `node:repl` duplicated capabilities already available natively via Web Standards (`crypto.subtle`, `ReadableStream`, `URL`) and **Bun 1.4.5** (`Bun.connect` + `socket.upgradeTLS()`, `Bun.serve`, `Bun.file().stat()/delete()`, `Bun.resolveSync`, `Bun.inspect`, `Bun.deepEquals`, `Bun.CryptoHasher`).
3. **Uncontrolled kernel boundary:** `node:async_hooks` (`AsyncLocalStorage`) and POSIX directory/watch/exclusive-open syscalls (`node:fs*`) were imported across 37 files in 10+ packages instead of being isolated behind stable runtime adapters.
4. **No automated regression barrier:** Without CI release gates, external runtime deps or stray `node:*` imports could silently re-enter packages over time.

---

## 2. Decision

### 2.1 Zero External Runtime Dependencies Across All 19/19 Packages

Every workspace package (`packages/*/package.json`) **MUST** have **0 external npm runtime dependencies** — `dependencies` **MAY ONLY** reference `@bunest/*` workspace packages.

All four previously external runtime dependencies are replaced by dedicated, spec-compliant, Bun-native engines:

1. **Zero-Dep ECMAScript Reflect Metadata Shim (`@bunest/core`)**:
   - `packages/core/src/common/metadata/reflect-shim.ts` implements all 10 ECMAScript Reflect Metadata Proposal methods (`defineMetadata`, `getMetadata`, `getOwnMetadata`, `hasMetadata`, `hasOwnMetadata`, `deleteMetadata`, `getMetadataKeys`, `getOwnMetadataKeys`, `metadata`, `decorate`) backed by a single-realm `globalThis[Symbol.for("bunest:reflect:metadata")]` `WeakMap`, plus ambient `declare global { namespace Reflect }` typings.
   - Installation is **idempotent** (never overwrites pre-existing `Reflect.*Metadata` methods if an application also imports `reflect-metadata`).
   - Auto-loaded by all `@bunest/core` entrypoints; applications no longer need `reflect-metadata` in `package.json` or `import "reflect-metadata"` boilerplate.

2. **Zero-Dep `TextEditor` & Bunest Native TypeScript AST Engine (`@bunest/cli`, `apps/vscode-bunest`)**:
   - `packages/cli/src/analyzer/text-editor.ts` replaces `magic-string` with a chunk-list text editor supporting overlapping/interleaved edits (`appendLeft`, `appendRight`, `overwrite`, `prepend`, `prependLeft`, `remove`, `toString`).
   - `packages/cli/src/ast/` replaces `ts-morph` with a purpose-built TypeScript lexer, recursive-descent parser, cross-file import/type resolver, and `BunestProject`/`BunestSourceFile` facade, delivering **~59x faster** project scanning and shrinking the `vscode-bunest` extension bundle while preserving 100% byte-for-byte `.d.ts` typegen and diagnostic parity (`BUNEST001..007`, `BUNEST_REPO001..007`, `BUNEST_MACRO001..005`).

3. **Zero-Dep Native GraphQL October 2021 Spec Engine (`@bunest/graphql`)**:
   - `packages/graphql/src/engine/` replaces the external `graphql` npm package with a full October 2021 spec implementation: lexer (UTF-8 BOM, block strings, exact source locations), executable + SDL recursive-descent parser, AST visitor/printer, built-in scalars & schema type system with duck-typed external schema interop (`Symbol.toStringTag`), full introspection (`__Schema`..`__Directive`), SDL builder/printer/sorter, all 26 `specifiedRules` + `NoSchemaIntrospectionCustomRule`, and execution/subscription engine preserving single-tick `BunestDataLoader` batching.

### 2.2 Complete Elimination of 14/16 `node:*` Built-in Modules via Web Standards & Bun 1.4.5

All `node:path`, `node:assert/strict`, `node:diagnostics_channel`, `node:http`, `node:net`, `node:tls`, `node:os`, `node:util`, `node:url`, `node:module`, `node:repl`, `node:stream`, and `node:crypto` imports are eliminated from `packages/*/src/` and `apps/docs/src/`:

- **Shared pure-TS / Bun-native primitives in `@bunest/core`**:
  - `path.util.ts` (POSIX + Win32 `basename`, `dirname`, `extname`, `isAbsolute`, `join`, `normalize`, `relative`, `resolve`, `sep`)
  - `assert.util.ts` (`strictAssert` + `AssertionError` backed by `Bun.deepEquals(a, b, true)`)
  - `net.util.ts` (RFC 3986/4291/6874 `isIp`, `isIpv4`, `isIpv6`)
  - `runtime-info.util.ts` (`getHostname` via `process.env.HOSTNAME` / `Bun.spawnSync(["hostname"])`, `getCpuCount` via `navigator.hardwareConcurrency`, `getPlatform`, `getArch`)
  - `crypto.util.ts` (constant-time XOR `timingSafeEqualBytes`, unbiased rejection-sampling `randomInt`/`randomIntRange` on `crypto.getRandomValues`, `Bun.CryptoHasher`)
  - `diagnostics-channel.ts` (`DiagnosticChannel`, `diagnosticsChannel`/`channel`, `hasSubscribers`, `publish`, `subscribe`, `unsubscribe` on `globalThis[Symbol.for("bunest:diagnostics:channels")]`)
  - `http-compat.interface.ts` (`HttpIncomingHeaders`, `HttpServerResponseLike`, `HttpIncomingMessageLike`) & expanded `HTTP_STATUS_REASON_PHRASES`
- **Web Standards & Bun-native transport upgrades**:
  - **Networking & TLS:** `@bunest/mail` SMTP client uses native `Bun.connect()` + `socket.upgradeTLS()` for implicit TLS & STARTTLS and WHATWG `new URL()` for IDNA/Punycode; `@bunest/testing` HTTP bridge runs directly on `Bun.serve({ port: 0 })`; `@bunest/messaging` webhooks use native `fetch(..., { tls })`.
  - **WebCrypto (`crypto.subtle`) & Pure-TS Cryptography:** AES-256-GCM, HKDF-SHA256, JWS/JWT/JWKS (`HS/RS/PS/ES256–512`, `EdDSA`), DKIM signing (`RSA-SHA256`, `Ed25519`), PEM/DER/X.509/ECDSA-P1363 codecs, and legacy `$scrypt$` verification fallback (RFC 7914 over `Bun.CryptoHasher("sha256", key)`) run with zero `node:crypto`.
  - **Web Streams:** `@bunest/core/client`, `@bunest/storage`, `@bunest/mail`, and `@bunest/ai` operate natively on `ReadableStream<Uint8Array>`, `AsyncIterable<Uint8Array>`, and structural stdio interfaces with zero `node:stream`.
  - **Runtime ergonomics:** `ConsoleLogger`, `repl()`, optional dynamic module resolution (`Bun.resolveSync` + `require`), and `runStoreCli()` run with zero `node:util`, `node:repl`, or `node:module`.

### 2.3 Strict 2-File Kernel Adapter Quarantine

Two OS/runtime capabilities lack non-`node:*` globals in Bun 1.4.5:

1. **`packages/core/src/common/runtime/async-context.ts` (`ContextStorage<T>`)** — Auto-detects TC39 `globalThis.AsyncContext.Variable` when available and falls back to Bun's native `AsyncLocalStorage` from `node:async_hooks`.
2. **`packages/core/src/common/runtime/fs-runtime.ts`** — Quarantines POSIX directory, symlink, `statfs`, filesystem watcher, and exclusive-open (`O_EXCL` / `wx`) syscalls (`node:fs` / `node:fs/promises`) behind structural, runtime-neutral interfaces (`FsStats`, `FsDirent`, `FsWatcher`, `FsStatFs`, `FsFileHandle`), while file-level reads, writes, deletes, and globs use `Bun.file()`, `Bun.write()`, and `Bun.Glob`.

These **two files are the ONLY files in the entire monorepo (`packages/*/src/` and `apps/docs/src/`) permitted to import `node:*` modules**. All other 18/19 packages and `apps/docs` have **0 `node:*` imports**.

### 2.4 Permanent CI Release Verification Gates (`scripts/verify-release.ts`)

`bun run verify:release` permanently enforces two blocking gates:

1. **Zero External Runtime Dependencies Gate:** Fails if any `packages/*/package.json` declares a runtime dependency outside `@bunest/*`.
2. **Node Built-in & External Import Quarantine Gate:** Scans all `packages/*/src/**/*.{ts,js}` and `apps/docs/src/**/*.{ts,js}` and fails on any `node:*` import outside the 2-file allowlist or any `reflect-metadata`, `ts-morph`, `magic-string`, or `graphql` import in `packages/*/src/`.

## 3. Consequences

### Positive

- **19/19 packages = 0 external npm runtime dependencies** (`dependencies` contains only `@bunest/*` workspace links).
- **18/19 packages + `apps/docs` = 0 `node:*` imports** (reduced from 153 imports across 16 modules to 2 quarantined adapter files in `@bunest/core`, `-98.7%`).
- Faster installs, dramatically smaller production bundles, ~59x faster CLI AST analysis, and zero `import "reflect-metadata"` boilerplate for user applications.
- Forward-ready for TC39 `AsyncContext.Variable` and future Bun POSIX directory APIs with single-file swap points.

### Trade-offs & Migration Notes

- `StorageDownload.body` (`@bunest/storage`) and `HttpClient` `responseType: "stream"` (`@bunest/core/client`) now return standard Web `ReadableStream<Uint8Array>` (which natively implements `AsyncIterable<Uint8Array>` for `for await (const chunk of stream)`).
- WebCrypto-backed internal encryption/signing primitives (`SecretCodec`, `ResponseCodec`, `AesGcmPayloadCodec`, `DkimSigner`, `JwtSigner.sign`) are `async` (`Promise`-returning).
- Root `devDependencies` retains `typescript` and `@types/bun` for IDE/CI typechecking, plus `class-validator` and `class-transformer` solely for upstream dual-engine parity tests (`packages/validation/test/native-*.spec.ts`) and head-to-head comparison benchmarks.

## 4. Phase 2 Addendum: Full Repo-Wide Bun-Native Completion (2026-11-23)

Following the initial Phase 1 framework-source isolation, Phase 2 extended the zero-external-dep / 2-adapter `node:*` quarantine across the **entire repository** (tests, apps, CLI templates, examples, benchmarks, CI, and release gates):

1. **Repo-Wide Zero `node:*` Completion (Outside the 2 Bun 1.4.5 Kernel Adapters):**
   - Eliminated all remaining `node:*` and bare Node built-in imports from `packages/*/test/**`, `apps/docs/test/**`, `apps/vscode-bunest/**`, `examples/**`, `scripts/**`, `tests/**` (full NestJS conformance suite + root integration tests), and all Bun benchmark harnesses (`benchmarks/run.ts`, `benchmarks/http-benchmark.ts`, `benchmarks/validation-benchmark.ts`, `benchmarks/nestjs-comparison/src/{runner,measure-deps}.ts`). Only the 2 quarantined kernel adapters in `@bunest/core` (`async-context.ts`, `fs-runtime.ts`) and out-of-scope Node/NestJS comparison baseline servers (`benchmarks/nestjs-comparison/src/server-nestjs-*.ts`) retain Node built-ins.
   - Upgraded `statPath()` in `packages/core/src/common/runtime/fs-runtime.ts` to native `Bun.file(path).stat()` and eliminated all remaining `setImmediate()` calls (4) and `process.version` references in `packages/*/src/`.
2. **CLI Scaffolds & Templates Migrated to `@bunest/validation` (`@bunest/cli`):**
   - Updated `bunest new` (`project.templates.ts`) to emit `"@bunest/validation": "^0.1.0"` (replacing `"class-validator"` / `"class-transformer"`), `"engines": { "bun": ">=1.4.5" }`, and `Number(Bun.env.PORT ?? 3000)` in `src/main.ts` with zero `reflect-metadata` boilerplate.
   - Updated `bunest generate` (`schematic.templates.ts`) across all DTO, endpoint, and CRUD resource templates to import decorators from `"@bunest/validation/validator"`, and verified real `bun check` + `bun test` smoke execution without `class-validator` or `class-transformer` installed.
3. **VS Code Extension Bundling (`apps/vscode-bunest`):**
   - Replaced `esbuild` and `esbuild.config.mjs` with a Bun-native `build.ts` using `Bun.build({ target: "node", format: "cjs", external: ["vscode"] })` + workspace alias plugin and `--watch` via `@bunest/core` `watchPath`.
   - Removed `esbuild` from `apps/vscode-bunest/package.json` and switched `typecheck` from `tsc --noEmit` to `bun check`.
4. **CI & Workspace Alignment:**
   - Updated `.github/workflows/ci.yml` Bun matrix & coverage jobs to **Bun `1.4.5`**, unified typechecking on `bun run typecheck` (`bun check`, removing redundant `bunx tsc --noEmit`), and removed the obsolete root `test.ts` scratch file.
5. **Expanded Permanent Release Gates (`scripts/verify-release.ts`):**
   - Extended the `0 node:*` quarantine scan to cover `packages/*/test/**`, `apps/*/test/**`, `apps/vscode-bunest/build.ts`, `examples/*/test/**`, `tests/**`, and Bun benchmark harnesses.
   - Added permanent enforcement banning `esbuild` across `packages/` and `apps/` and banning `setImmediate(` in `packages/*/src/**`.
   - Upgraded the CLI clean-project smoke test to assert `"@bunest/validation"`, absence of `"class-validator"` / `"class-transformer"`, `"engines": { "bun": ">=1.4.5" }`, and `"@bunest/validation/validator"` in generated resource DTOs, plus verification that `apps/vscode-bunest/dist/extension.js` is built and non-empty.
