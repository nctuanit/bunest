# ADR-002: Legacy TypeScript Decorators (`experimentalDecorators` + `emitDecoratorMetadata`)

- **Status:** Accepted
- **Date:** 2026-11-20
- **Related:** [ADR-001](./ADR-001.md), [ADR-003](./ADR-003.md), [ADR-004](./ADR-004.md), [ADR-005](./ADR-005.md)

## Context

Bunest targets NestJS-style ergonomics: constructor dependency injection via parameter types, parameter decorators (`@Body()`, `@Param()`, `@Query()`), and `class-validator` + `class-transformer` DTOs. TC39 Stage 3 standard decorators do NOT support parameter decorators and do NOT emit `design:paramtypes` reflection metadata, breaking both constructor DI inference and `class-validator` ecosystem compatibility.

## Decision

1. **Legacy TypeScript decorators are the official decorator model** for Bunest across classes, methods, properties, and parameters. Standard TC39 decorators and `accessor` syntax are NOT used as the default API.
2. **Mandatory `tsconfig.json` compiler options:**
   ```json
   {
     "compilerOptions": {
       "target": "ESNext",
       "module": "Preserve",
       "moduleResolution": "bundler",
       "experimentalDecorators": true,
       "emitDecoratorMetadata": true,
       "verbatimModuleSyntax": true,
       "strict": true,
       "noEmit": true,
       "types": ["bun"]
     }
   }
   ```
   - **`verbatimModuleSyntax: true` is safer and empirically verified on Bun 1.4.3:**
     - Bun's single-file transpiler (`__legacyDecorateClassTS` / `__legacyMetadataTS`) preserves runtime value imports referenced in decorated constructor/method signatures. If a TypeScript `interface` or `type` is value-imported (`import { Foo }`) and referenced in a decorated signature, Bun preserves the runtime import and **crashes at runtime** (`SyntaxError: Export named 'Foo' not found`) and fails `bun build` regardless of `verbatimModuleSyntax`.
     - With `verbatimModuleSyntax: true`, `bun check` catches missing `import type` on interfaces/types (`TS1484`) at typecheck time while **allowing** value imports of runtime classes (`import { CreateUserDto }`, `import { UsersService }`) used in decorator signatures (`design:paramtypes` preserves the class constructor, and both `bun check` and `bun build` exit 0).
     - **Import rule:** Always value-import DI service classes and DTO classes (`import { CreateUserDto }`), and always `import type` TypeScript interfaces and type aliases (`import type { UserRecord }`). Never `import type` a DI class or DTO class that needs `design:paramtypes` reflection (doing so erases its runtime metadata to `Object`).
3. **`reflect-metadata` bootstrap requirement:** Applications MUST execute `import "reflect-metadata";` once at the entrypoint **before** importing decorated modules, controllers, or DTOs.
4. **Decoupled metadata layer:** All internal metadata reads/writes MUST go through `@bunest/common`'s `MetadataRegistry` and `Reflector` using namespaced `Symbol` keys (never bare string keys), isolating direct `Reflect.*` usage behind one module.
5. **Inheritance safety invariant:** Every Bunest decorator that appends to array/map metadata (routes, parameters, guards, pipes, interceptors, filters, headers) MUST read own metadata (or clone inherited metadata) before writing on the target—NEVER mutating a parent class's metadata container in place.
6. **Runtime verification rule:** Static typechecking (`bun check` / `tsc --noEmit`) does not prove Bun's transpiler emits runtime metadata accurately. The test suite MUST maintain a runtime spike test (`bun test`) verifying `design:paramtypes`, `design:type`, and `design:returntype` for both constructors and methods across separate imported modules.

## Known `design:paramtypes` Limitations (Explicit Contract)

`emitDecoratorMetadata` cannot represent TypeScript-only constructs at runtime:
- **Interfaces / type aliases / unions:** Emit `Object`. Consumers MUST use `@Inject(TOKEN)` for DI and explicit pipes/validators for HTTP inputs.
- **Generics:** `Array<CreateUserDto>` emits `Array`. Nested/array DTOs MUST declare `@Type(() => CreateUserDto)` + `@ValidateNested({ each: true })`.
- **Circular class references:** May emit `undefined`. Consumers MUST use `@Inject(forwardRef(() => Target))`.

## Consequences

- **Positive:** Full compatibility with NestJS constructor DI, legacy parameter decorators, `class-validator`, and `class-transformer` without requiring a custom AST build plugin.
- **Negative:** Tied to TypeScript's legacy decorator emit and Bun's transpiler implementation of `emitDecoratorMetadata`.
- **Mitigation:** Pin TypeScript and Bun versions in CI, isolate all metadata access in `MetadataRegistry`, and keep runtime reflection tests in the core CI gate.
