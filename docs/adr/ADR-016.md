# ADR-016: 37 → 19 Package Consolidation (6 Domains, ESM Subpath Exports) & Bun 1.4.5 Native API Alignment

- **Status:** Accepted
- **Date:** 2026-11-22
- **Amends:** [ADR-001](./ADR-001.md) (raises minimum runtime baseline to **Bun `>= 1.4.5`**), [ADR-015](./ADR-015.md) (exposes validation & transformer engines via `@bunest/validation/validator` and `@bunest/validation/transformer` subpaths instead of two separate standalone stub packages)
- **Related:** [ADR-002](./ADR-002.md), [ADR-008](./ADR-008.md), [ADR-013](./ADR-013.md), [ADR-014](./ADR-014.md)

---

## Context

Prior to this decision, the Bunest monorepo had grown to **37 workspace packages** (35 feature packages plus 2 standalone validation stub packages). Three structural issues emerged:

1. **Package Fragmentation & High Onboarding Friction:** A typical Bunest application had to install and align versions across 8–12 separate `@bunest/*` packages (`@bunest/common`, `@bunest/core`, `@bunest/http`, `@bunest/config`, `@bunest/http-client`, `@bunest/websockets`, `@bunest/i18n`, `@bunest/authentication`, `@bunest/authorization`, `@bunest/events`, `@bunest/cqrs`, `@bunest/locks`, `@bunest/idempotency`, etc.) even when those modules formed tightly cohesive domains.
2. **Duplicate Implementations Across Packages:** Several utilities were duplicated across workspace boundaries — `packages/security/src/storage` duplicated `@bunest/storage`, `uuidv7()` had 3 independent copies (`common`, `outbox`, `webhooks`), and `security/src/headers` duplicated `compileSecurityHeaders()` from `@bunest/core/http`.
3. **Under-Utilized Bun 1.4.5 Native APIs:** Multiple modules still relied on Node.js compatibility layers (`node:zlib`, `node:dns/promises`, `node:net`, `node:string_decoder`, `node:timers/promises`, `node:events`, `node:crypto` hashes/HMAC, manual cookie serialization, manual HTML escaping, scrypt-default password hashing, custom S3 SigV4 XML parsing, and missing first-class `Bun.RedisClient` / `Bun.S3Client` / `Bun.SQL` adapters).

---

## Decision

### 1. Balanced Consolidation: 37 → 19 Workspace Packages Across 6 Domains

Bunest consolidates its workspace from **37** to **19** canonical packages grouped into **6 functional domains**, using strict **ESM subpath exports (`package.json#exports`)** for tree-shaking and clean domain boundaries:

| Domain | Packages (19 total) | Merged Modules & Subpath Exports |
| --- | --- | --- |
| **1. Core & Validation (2)** | `@bunest/core`, `@bunest/validation` | `@bunest/core` merges `common`, `core`, `http`, `config`, `http-client`, `websockets`, `i18n` via `.`, `./common`, `./http`, `./config`, `./client`, `./ws`, `./i18n`. `@bunest/validation` adds `./validator`, `./transformer`, `./standard-schema` (replacing standalone `class-validator` / `class-transformer` package directories). |
| **2. Security (1)** | `@bunest/security` | Merges `security`, `authentication`, `authorization` via `.`, `./auth`, `./authz`, `./jwt`, `./throttler`, `./testing`. Removes duplicate `security/src/storage` in favor of `@bunest/storage`. |
| **3. API & AI (3)** | `@bunest/swagger`, `@bunest/graphql`, `@bunest/ai` | `@bunest/graphql` merges `apollo` as `./apollo`. `@bunest/ai` merges `mcp` as `./mcp` and `./mcp/testing` alongside `./testing`, `./workflows`. |
| **4. Data & Integrations (5)** | `@bunest/orm`, `@bunest/cache`, `@bunest/storage`, `@bunest/mail`, `@bunest/elasticsearch` | Adds granular subpaths: `@bunest/cache/redis`, `@bunest/storage/{s3,local,memory}`, `@bunest/mail/{smtp,templates}` alongside `@bunest/orm/{plugin,store,postgres,mysql,testing}`. |
| **5. Distributed & Async (5)** | `@bunest/messaging`, `@bunest/jobs`, `@bunest/resilience`, `@bunest/microservices`, `@bunest/workflows` | `@bunest/messaging` merges `events` (`./events`), `cqrs` (`./cqrs`), `outbox` (`./outbox`, `./outbox/{testing,postgres,mysql}`), `webhooks` (`./webhooks`, `./webhooks/{testing,postgres,mysql}`), with optional peer `@bunest/orm` and bins `nest-outbox`, `nest-webhooks`. `@bunest/jobs` merges `queues` (`./queues`, `./redis`) and `scheduler` (`./scheduler`). `@bunest/resilience` merges `locks` (`./locks`, `./locks/testing`) and `idempotency` (`./idempotency`, `./idempotency/testing`). |
| **6. DX & Ops (3)** | `@bunest/observability`, `@bunest/testing`, `@bunest/cli` | `@bunest/observability` exposes granular `./tracing`, `./metrics`, `./health`, `./devtools` subpaths. |

### 2. Strict DAG Decoupling (`@bunest/core` ↔ `@bunest/validation`)

To eliminate any circular dependency when merging `common` + `http` + `core`:

- `@bunest/core` owns zero-external-dep validation primitives and lazy hooks inside `packages/core/src/common/validation/` (`ValidationPipe`, `StandardSchemaValidationPipe`, `SchemaValidationPipe`, `ClassSerializerInterceptor`, `MappedTypes`, `entity-validator`) without importing `@bunest/validation`.
- `@bunest/validation` depends strictly **one-way** on `@bunest/core` and provides the full validation/transformer subpath exports (`./validator`, `./transformer`, `./standard-schema`).
- Across all 19 packages: **16/19 have zero external npm runtime dependencies** (after Phase 4 replaced the `class-validator`/`class-transformer` runtime bridge in `@bunest/validation` with the zero-dep compile-once Bun-native engine per [ADR-015](./ADR-015.md)), **0 cross-package DAG cycles**, and **0 intra-package runtime or type-only circular imports**.

### 3. Minimum Runtime Baseline Raised to Bun `>= 1.4.5` & Native API Alignment

All 19 packages declare `"engines": { "bun": ">=1.4.5" }` and standardize on native Bun 1.4.5 APIs where parity and security are preserved or improved:

- **UUID & Hashing:** Single canonical `uuidv7()` backed by `Bun.randomUUIDv7()` and `uuidv4()` backed by `crypto.randomUUID()`; SHA-256/MD5/HMAC hashing via `Bun.CryptoHasher` across `core`, `graphql`, `resilience`, `messaging`, `mail`, `storage`, `orm`, and `workflows`.
- **Compression & Escaping:** Zero `node:zlib` across the monorepo — `Bun.deflateSync()` / `Bun.inflateSync()` (+ RFC 1950 header + `Bun.hash.adler32()` for Devtools zlib payloads). Native `Bun.escapeHTML()` in `mail`, `swagger`, and `graphql`.
- **Storage & SQL & Redis:** Native `BunS3Disk` (`Bun.S3Client` / `Bun.s3`), `Bun.XML.parse` for S3 XML, `Bun.file().slice().stream()` for `LocalDisk`; native `Bun.RedisClient` adapters (`createBunRedisCacheAdapter`, `createBunRedisQueueAdapter`, and `Transport.REDIS` `{ url }` mode); native `createBunSqlExecutor` (`Bun.SQL`) in `@bunest/orm/store`.
- **Security & HTTP:** `Bun.password` (`argon2id` default, preserving legacy `$scrypt$` verification + `needsRehash`), `Bun.Cookie` serialization in `@bunest/core/http`, `Bun.CSRF.generate` / `Bun.CSRF.verify` in `@bunest/security/auth`, and unified `compileSecurityHeaders()` delegation.
- **Networking, Cron & Config:** `Bun.connect()` TCP probes in `@bunest/observability/health` (normalizing `ECONNREFUSED`/`ECONNRESET` messages for NestJS Terminus parity), `Bun.dns.lookup()` + `TextDecoder` in `@bunest/messaging/webhooks`, `Bun.cron.parse` fast-path in `@bunest/jobs/scheduler`, and `Bun.YAML.parse` / `Bun.TOML.parse` / `Bun.JSONC.parse` loaders in `@bunest/core/config` and `@bunest/core/i18n`.
- **Intentional `node:*` Retentions:** `node:async_hooks` (`AsyncLocalStorage`), `node:diagnostics_channel`, `node:fs`/`node:path`, `node:crypto` (WebCrypto/AES-GCM/timingSafeEqual/scrypt fallback), `node:net`/`node:tls` (SMTP STARTTLS full `tls.ConnectionOptions` parity & IP checks), and `node:http` (Supertest bridge in `@bunest/testing`).

### 4. Clean 1-Shot Refactor via Monorepo Codemod

Rather than shipping temporary re-export shim packages, imports across the monorepo (`packages/`, `apps/`, `examples/`, `tests/`, `benchmarks/`) are migrated in one shot using `scripts/codemods/migrate-consolidated-imports.ts`, which external adopters can also run directly on their repositories.

---

## Normative Invariants

1. **Exact 19-Package Topology & Subpath Integrity:** Every subpath in `package.json#exports` across all 19 packages MUST resolve to a built `dist/` ESM bundle and valid TypeScript declaration entry, enforced by `bun run verify:release`.
2. **Zero Cycles:** Cross-package DAG cycles MUST equal `0`, and intra-package runtime & type-only cycles MUST equal `0`.
3. **Engine Alignment:** All 19 workspace `package.json` manifests MUST declare `"engines": { "bun": ">=1.4.5" }`.
4. **Zero Banned Node Shims:** `node:zlib`, `node:string_decoder`, `node:timers/promises`, `node:events`, and `node:dns/promises` MUST NOT appear in `packages/*/src/`.
5. **No Duplicate Storage / UUID Utilities:** Storage APIs live exclusively in `@bunest/storage`; `uuidv7()` lives canonically in `@bunest/core` (`Bun.randomUUIDv7()`).

---

## Consequences

- **Positive:** 49% fewer packages to install, version, build, and maintain (37 → 19); flatter dependency DAG (17 of 19 packages depend solely on `@bunest/core`); zero duplicate storage/UUID/header implementations; first-class Bun 1.4.5 native Redis, S3, SQL, Argon2id, CSRF, Cookie, XML, YAML/TOML/JSONC, and CryptoHasher performance; faster workspace builds and simpler mental model.
- **Negative:** Breaking import paths for pre-consolidation package names (`@bunest/common`, `@bunest/events`, `@bunest/authentication`, etc.) and raising the minimum Bun version from `1.4.3` to `1.4.5`.
- **Mitigation:** Provided automated AST/regex codemod (`scripts/codemods/migrate-consolidated-imports.ts`) plus full old→new mapping table in documentation and release notes.
