# ADR-010: Response Serialization Contract, Status Codes & Response Decorators

- **Status:** Accepted
- **Date:** 2026-11-20
- **Related:** [ADR-001](./ADR-001.md), [ADR-006](./ADR-006.md), [ADR-008](./ADR-008.md)

## Context

Bun's HTTP layer operates directly on native Web `Response` objects, `BunFile`, `Blob`, `ReadableStream`, and `Uint8Array`, whereas NestJS controllers typically return plain JavaScript objects, primitives, or `void`. Without a strict serialization contract, implementations diverge on `Content-Type`, default status codes (`201` for `POST`), `null`/`undefined` handling, `Set-Cookie` merging, and native `Response` passthrough.

## Decision

### 1. Default HTTP Status Codes & Precedence

Status code resolution priority (highest to lowest):

1. Returned native `Response.status` (when handler/interceptor returns `value instanceof Response`).
2. Status explicitly set at runtime via `@Res()` (`ResponseContext.status(code)`).
3. Dynamic redirect status returned on a `@Redirect()` handler (`{ url, statusCode }`).
4. `@HttpCode(code)` decorator on the handler method.
5. `@Redirect(url, statusCode)` decorator default (`302`).
6. HTTP method default:
   - **`POST` -> `201 Created`**
   - **`GET`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `HEAD` -> `200 OK`**

### 2. Return Value Serialization Matrix

Evaluated in strict top-to-bottom priority order after all interceptors unwind:

| Priority | Returned Value Type                                                                   | HTTP Body                                             | Default `Content-Type` (if unset)           | Notes                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | `value instanceof Response`                                                           | **Passthrough** (unmodified body)                     | Preserved from `Response`                   | Status from `Response` wins. Framework merges CORS, `Set-Cookie`, and missing `@Header()` headers without overwriting explicit headers on `Response`. |
| 2        | `@Redirect()` route                                                                   | Empty (`null`)                                        | None                                        | Uses returned `{ url, statusCode? }` if present, else decorator `(url, statusCode=302)`. Sets `Location` header.                                      |
| 3        | `@Sse()` route (`AsyncIterable<SseMessageEvent>` / `ReadableStream<SseMessageEvent>`) | SSE UTF-8 stream (`id:`, `event:`, `retry:`, `data:`) | `text/event-stream; charset=utf-8`          | Sets `Cache-Control: no-cache, no-transform`, `Connection: keep-alive`. Cancels upstream iterator on `request.signal` abort.                          |
| 4        | `value instanceof ReadableStream`                                                     | Streamed directly                                     | `application/octet-stream`                  | Zero-buffering native Web stream passthrough.                                                                                                         |
| 5        | `value instanceof Blob` (includes `BunFile` from `Bun.file()`)                        | Passed directly to `new Response(blob, ...)`          | `blob.type \|\| "application/octet-stream"` | Preserves Bun's native zero-copy file streaming (`sendfile`).                                                                                         |
| 6        | `value instanceof Uint8Array` / `ArrayBuffer` / `ArrayBufferView`                     | Raw binary bytes                                      | `application/octet-stream`                  | Direct binary response without JSON encoding.                                                                                                         |
| 7        | `null` or `undefined`                                                                 | Empty (`null`)                                        | None                                        | Returns `new Response(null, { status, headers })`.                                                                                                    |
| 8        | `string`                                                                              | UTF-8 string                                          | `text/plain; charset=utf-8`                 | Overridable via `@Header("Content-Type", "text/html; charset=utf-8")` etc.                                                                            |
| 9        | `number` or `boolean`                                                                 | `JSON.stringify(value)`                               | `application/json; charset=utf-8`           | Valid JSON primitive (`42`, `true`), round-trippable with `res.json()`.                                                                               |
| 10       | Plain object / Array / Class instance                                                 | `JSON.stringify(value)`                               | `application/json; charset=utf-8`           | Respects `toJSON()`. Circular structure throws `InternalServerErrorException` (500) handled by Exception Filter.                                      |

### 3. RFC 9110 Empty-Body Enforcement

For responses with status **`204 No Content`**, **`304 Not Modified`**, **`1xx`**, or requests with HTTP method **`HEAD`**:

- The serializer MUST construct `new Response(null, { status, headers })` with an empty body regardless of handler return value.

### 4. Header & Cookie Merge Precedence

Headers are merged into a native `Headers` instance in increasing priority order (later entries override earlier entries for single-value headers):

1. Serializer default `Content-Type`
2. Configured CORS headers (from Security/CORS stage)
3. Static `@Header(name, value)` decorator entries (in declaration order)
4. Dynamic headers set on `@Res()` (`ResponseContext.header(name, value)`)
5. Explicit headers already present on a returned native `Response`

**Multi-value `Set-Cookie` invariant:** Cookies set via `ResponseContext.cookie(name, value, options)` / `clearCookie()` and `@Header("Set-Cookie", ...)` MUST always be added with `headers.append("Set-Cookie", ...)`—NEVER `headers.set()`—so multiple cookies are preserved cleanly.

### 5. Native `Response` Passthrough + `@Res()` Interaction

Because Bun uses Web `Response` (not Express's mutable socket stream), `@Res()` injects a lightweight `ResponseContext` builder (`status(code)`, `header(k, v)`, `appendHeader(k, v)`, `cookie(name, val, opts)`, `clearCookie(name, opts)`) that accumulates metadata applied during serialization. Handlers using `@Res()` still return their body normally (like NestJS `@Res({ passthrough: true })`), OR return a native `new Response(...)` directly to take full control of status, headers, and streaming body.

### 6. SSE Wire Format (`SseMessageEvent`)

```ts
export interface SseMessageEvent {
  data: string | object;
  id?: string;
  type?: string;
  retry?: number;
}
```

- Object `data` is serialized via `JSON.stringify(event.data)`.
- Multi-line string `data` emits one `data: <line>\n` per line.
- Each event terminates with `\n\n`.

## Consequences

- **Positive:** Native zero-copy Bun streaming for files/blobs/streams; idiomatic NestJS defaults (`201` on `POST`, JSON for objects, `@HttpCode`/`@Header`/`@Redirect`); zero Express response-shim complexity.
- **Negative:** Express-style `res.status(200).send(...)` is replaced by returning values / native `Response` + `ResponseContext`.
- **Mitigation:** Document `@Res()` `ResponseContext` and native `Response` passthrough clearly in migration docs.
