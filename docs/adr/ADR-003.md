# ADR-003: NestJS-Style Controllers + Method Decorators

- **Status:** Accepted
- **Date:** 2026-11-20
- **Related:** [RFC-001](../rfcs/RFC-001-controller-routing.md), [ADR-004](./ADR-004.md), [ADR-006](./ADR-006.md), [ADR-012](./ADR-012.md)

## Context

Two routing architectures were considered:
1. **Class-per-endpoint** (`@Get("/users") class ListUsersEndpoint extends BaseMethod { handle() {} }`), where every endpoint is its own class.
2. **NestJS-style controllers** (`@Controller("/users") class UsersController { @Get() list() {} @Post() create() {} }`), where a controller class groups related HTTP endpoints as methods.

## Decision

1. **Bunest adopts NestJS-style controller classes with HTTP method decorators** as the single official HTTP routing API.
2. **No `BaseMethod` / `PostMethod` inheritance hierarchy:** Public routing APIs MUST NOT require controllers or handlers to extend a framework base class.
3. **One controller, many routes:** Each `@Controller()` class may define zero or more decorated route methods (`@Get`, `@Post`, `@Put`, `@Patch`, `@Delete`, `@Options`, `@Head`, `@All`, `@Sse`). Undecorated methods on a controller class are ordinary helper methods and are NOT exposed as routes.
4. **Stateless singleton controllers by default:**
   - Controller instances default to `Scope.SINGLETON` and are instantiated once at bootstrap with constructor DI.
   - Controllers MUST NOT store per-request mutable state on `this`.
   - Controllers that require request-scoped providers MUST opt in explicitly via `@Controller({ path: "/users", scope: Scope.REQUEST })` (see [ADR-012](./ADR-012.md)).
5. **Sync and async handlers:** Route methods may return values synchronously or return a `Promise<T>`, and may return plain data, streams, files, or a native `Response` (see [ADR-010](./ADR-010.md)).

## Consequences

- **Positive:** Immediate familiarity for NestJS developers; cohesive resource grouping; shared controller-level prefix, DI dependencies, guards, pipes, interceptors, and exception filters; lower boilerplate than class-per-endpoint.
- **Negative:** Requires scanning both class and method metadata (including inherited methods) at bootstrap, and requires enforcing statelessness on singleton controllers.
- **Mitigation:** Compile controller methods into bound closures at bootstrap ([RFC-001](../rfcs/RFC-001-controller-routing.md)), enforce copy-on-write inheritance safety ([ADR-002](./ADR-002.md)), and fail fast on singleton-to-request scope leaks ([ADR-012](./ADR-012.md)).
