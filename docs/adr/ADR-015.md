# ADR-015: Bun-Native Validation & Transformation Engine (`@bunest/validation/validator` & `@bunest/validation/transformer`)

- **Status:** Accepted *(amended by [ADR-016](./ADR-016.md) subpath consolidation)*
- **Date:** 2026-11-22
- **Supersedes / Amends:** [ADR-005](./ADR-005.md) (replaces third-party `class-validator` & `class-transformer` as the default implementation while preserving the `PipeTransform` seam and all [ADR-009](./ADR-009.md) security defaults)
- **Related:** [ADR-001](./ADR-001.md), [ADR-002](./ADR-002.md), [ADR-008](./ADR-008.md), [ADR-009](./ADR-009.md), [ADR-013](./ADR-013.md), [ADR-014](./ADR-014.md), [ADR-016](./ADR-016.md)

---

## Context

Benchmark measurements in `benchmarks/nestjs-comparison/RESULTS.md` and `benchmarks/RESULTS.md` revealed that upstream `class-validator@0.14.x` + `class-transformer@0.5.x` were the single largest performance, memory, and dependency bottleneck in Bunest:

1. **Dependency & Disk Bloat:** Core Bunest (`@bunest/core` + `@bunest/common` + `@bunest/http`) weighs **1.27 MB** with **1 external npm dependency** (`reflect-metadata`). Adding upstream `class-validator` + `class-transformer` pulled in 5 extra npm packages (`validator`, `libphonenumber-js`, `@types/validator` in runtime `dependencies`) and inflated the stack by **+16.37 MB** (to **17.74 MB**).
2. **Hot-Path CPU & RSS Overhead:** On `POST /users/validated`, throughput dropped **~50%** compared to unvalidated `POST /users` (25,916 → 12,992 req/s) and RSS jumped **+17.7 MB** because upstream engines re-traverse prototype chains, re-query global metadata arrays, invoke `Reflect.getMetadata`, and allocate intermediate `Promise` chains on every single request—even when 100% of rules are synchronous.
3. **Maintenance & Dual-Storage Bugs:** Upstream `class-transformer@0.5.1` has been stagnant since 2021 and suffers from dual CJS/ESM `defaultMetadataStorage` splits, forcing fragile `createRequire("class-transformer/cjs/storage")` / `"class-transformer/esm5/storage"` workarounds in `@bunest/common` and `@bunest/validation`.
4. **Coercion & ReDoS Hazards:** Upstream `enableImplicitConversion` silently coerces `Boolean("false") === true` and `Number("") === 0`, and several third-party string regexes have historically suffered ReDoS regressions.

---

## Decision

### 1. Zero-Dependency Subpath Engines Inside `@bunest/validation`

Bunest ships two dedicated, Bun-native, zero-external-runtime-dependency subpath engines inside `@bunest/validation` (consolidated under [ADR-016](./ADR-016.md)):

- **`@bunest/validation/transformer`** (`packages/validation/src/transformer/`):
  - Full drop-in API parity with `class-transformer@0.5.x`: `plainToInstance`, `plainToClass`, `plainToClassFromExist`, `instanceToPlain`, `classToPlain`, `classToPlainFromExist`, `instanceToInstance`, `classToClassFromExist`, `serialize`, `deserialize`, `deserializeArray`, `ClassTransformer`, `TransformationType`, `@Expose`, `@Exclude`, `@Type` (including polymorphic `discriminator`), `@Transform`, `@TransformPlainToInstance`, `@TransformInstanceToPlain`, `@TransformInstanceToInstance`, and public `getMetadataStorage()` / `defaultMetadataStorage`.
  - **Safe `enableImplicitConversion: true`:** When explicitly enabled (still `false` by default per [ADR-009](./ADR-009.md)), string booleans parse strictly (`"true"`/`"1"` → `true`, `"false"`/`"0"` → `false`, unrecognized strings left untouched rather than coerced to `true`) and empty/whitespace strings are never silently coerced to `0`.
  - **Prototype pollution immunity by construction:** Never reads or assigns own `"__proto__"`, `"constructor"`, or `"prototype"` keys.
  - **Web/Bun built-in preservation:** Preserves `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, TypedArrays/`Buffer`, `URL`, `Blob`, `File`, `Headers`, `Request`, `Response`, `ReadableStream` without corrupting them into plain objects.

- **`@bunest/validation/validator`** (`packages/validation/src/validator/`):
  - Full drop-in API parity with `class-validator@0.14.x` (336/336 runtime exports): `validate`, `validateSync`, `validateOrReject`, `validateMaybeSync`, `canValidateSynchronously`, `Validator`, `ValidationError`, `ValidationTypes`, `MetadataStorage`, `getMetadataStorage`, `registerDecorator`, `ValidateBy`, `buildMessage`, `isValidationOptions`, `registerSchema`, `useContainer`, `getFromContainer`, `@Validate`, `@ValidatorConstraint`, `@ValidateNested`, `@ValidateIf`, `@ValidatePromise`, `@Allow`, `@IsOptional`, `@IsDefined`, and all ~105 built-in constraint decorators/predicates/constants.
  - **Zero external runtime dependencies:** All ~105 validators are implemented in pure TypeScript with linear-time, ReDoS-safe parsers/regexes (worst-case < 5 ms on 50 KB adversarial payloads). `IsPhoneNumber` ships with built-in E.164 + country prefix/length validation plus an optional `registerPhoneNumberValidator(fn)` hook for apps wanting carrier-level `libphonenumber-js` metadata.

### 2. Single-Realm `Symbol.for()` `WeakMap`-Backed Storage & Compile-Once Execution

- Both storages reside on `globalThis` via `Symbol.for("bunest:class-transformer:storage")` and `Symbol.for("bunest:class-validator:storage")` (with engines self-registered on `Symbol.for("bunest:class-transformer:engine")` and `Symbol.for("bunest:class-validator:engine")`), eliminating CJS/ESM dual-storage splits permanently and allowing `@bunest/core` + `@bunest/swagger` to resolve them in O(1) with zero circular workspace dependencies.
- Both storages back per-class metadata with **`WeakMap<Function, ...>`** (GC-safe for dynamically generated `PartialType`/`PickType`/`OmitType` DTO classes), track a monotonic mutation `epoch`, and expose public `cloneClassMetadata()` / `hasMetadataFor()` methods.
- Both engines compile each DTO class **once** into a flat monomorphic execution plan cached in a `WeakMap<Function, CompiledPlan>` (auto-invalidated on `epoch` change).
- **Zero `eval` / `new Function`:** Plans execute via tight monomorphic loops (`tryFastPlainToInstance` + compiled `__fastValidate` predicates) optimized by JavaScriptCore's FTL JIT, preserving strict CSP and `bun build --compile` compatibility.
- **Zero-Promise Sync Fast Path & Fused `ValidationPipe`:** `validateMaybeSync()` executes synchronous DTO graphs (both flat and nested) with zero intermediate `Promise` allocations and zero `Reflect.getMetadata()` calls on the hot path, fused directly into `ValidationPipe.transform()`.

### 3. Seamless Dual-Engine Coexistence (Zero Breaking Migration)

- `@bunest/core` (`ValidationPipe`, `ClassSerializerInterceptor`, `MappedTypes`, `@Entity()`, `ConfigModule`, `I18nValidationPipe`) and `@bunest/swagger` (`SchemaExplorer`, `DeepPartialType`) default to `@bunest/validation/validator` and `@bunest/validation/transformer`.
- When a DTO class carries metadata registered only in upstream npm `class-validator` or `class-transformer` (or when the caller supplies `validatorPackage` / `transformerPackage` overrides), Bunest automatically detects and falls back to the upstream package if installed. Existing NestJS apps can migrate incrementally without rewriting every DTO on day one.

---

## Normative Invariants

1. **Zero External Runtime Dependencies:** `@bunest/validation` MUST NOT declare any external npm package in `dependencies` (only `@bunest/core: workspace:*`).
2. **ADR-009 Preservation:** `ValidationPipe` MUST retain all conservative ADR-009 defaults (`whitelist: true`, `forbidNonWhitelisted: true`, `forbidUnknownValues: true`, `transform: true`, `enableImplicitConversion: false`, `validationError: { target: false, value: false }`, normalized HTTP 400 envelope).
3. **GC-Safe WeakMap Caching:** Both metadata storages and compilation caches MUST use `WeakMap<Function, ...>` so dynamically generated DTO classes (`PartialType`, etc.) are never retained strongly.
4. **Linear-Time Security:** All built-in string validators MUST be ReDoS-safe and reject catastrophic backtracking; all object transformations MUST guard against `"__proto__"`, `"constructor"`, and `"prototype"`.
5. **Zero Circular Dependencies:** `@bunest/validation` depends strictly one-way on `@bunest/core`, with zero cross-package DAG cycles and zero intra-package runtime or type-only circular imports (`bun run verify:release`).

---

## Consequences

- **Positive:** ~90% reduction in `@bunest/core + validation` disk footprint (17.74 MB → < 2 MB), 10x+ faster isolated transform+validate microbenchmarks, dramatically higher validated HTTP throughput, zero dual-storage CJS/ESM bugs, ReDoS-hardened validators, and full NestJS/Bunest ecosystem compatibility.
- **Negative:** Bunest owns maintenance of the ~105 built-in validators and transformer engine.
- **Mitigation:** Differential parity test suites run continuously against upstream `class-validator` and `class-transformer` (kept in root `devDependencies`), guaranteeing behavioral alignment alongside ReDoS and memory-leak regression suites.
