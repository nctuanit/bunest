# ADR-001: Bun-Only Runtime

- **Status:** Accepted
- **Date:** 2026-11-20
- **Related:** [ADR-002](./ADR-002.md), [ADR-010](./ADR-010.md), [ADR-011](./ADR-011.md), [ADR-012](./ADR-012.md)

## Context

Supporting Node.js, Express, Fastify, Deno, and Bun simultaneously introduces heavy abstraction layers (`IncomingMessage`/`ServerResponse` shims, adapter packages, lowest-common-denominator HTTP handling) that negate Bun's native performance and ergonomics. Bunest's goal is NestJS-style developer experience paired directly with Bun's native platform primitives.

## Decision

1. **Bun is the sole officially supported runtime** for Bunest (`>= 1.4.3` initial baseline; raised to `>= 1.4.5` by [ADR-016](./ADR-016.md)).
2. Core packages (`@bunest/common`, `@bunest/core`, `@bunest/http`, `@bunest/validation`, `@bunest/testing`) MUST build directly on Bun and Web Standards:
   - HTTP server & routing: `Bun.serve({ routes, fetch, websocket })`
   - HTTP primitives: native Web `Request`, `Response`, `Headers`, `URL`, `ReadableStream`, `Blob`
   - File & binary I/O: `Bun.file()`, `Bun.write()`, `Uint8Array`
   - Data & tooling: `bun:sqlite`, `Bun.sql`, `bun:test`, `Bun.build()`, `Bun.spawn()`
3. **No Express/Fastify/Node HTTP adapters in core:** `@bunest/core` and `@bunest/http` MUST NOT depend on `express`, `fastify`, or `node:http`. Third-party adapters, if ever needed, live outside core.
4. **Permitted Bun-native Node-compat APIs:** Built-in compatibility APIs natively implemented by Bun with zero external dependency overhead MAY be used where no Web Standard equivalent exists—specifically `AsyncLocalStorage` from `node:async_hooks` (see [ADR-012](./ADR-012.md)).
5. **Typechecking & Testing:**
   - Tests run on `bun:test` (`bun test`).
   - Type definitions target `@types/bun` (`"types": ["bun"]`).
   - CI validates both static typechecking via Bun 1.4.3's native multi-threaded `bun check` (fast typecheck; use `tsc --emitDeclarationOnly` when emitting `.d.ts` files for publishing) and actual Bun runtime behavior.

## Consequences

- **Positive:** Zero Node/Express translation overhead; direct zero-copy `BunFile`/`Response` passthrough; single runtime test matrix; native WebSocket and SQLite/SQL primitives without extra native bindings.
- **Negative:** Applications cannot run Bunest on Node.js or Deno without an external compatibility layer; Express/Fastify middleware cannot be dropped in directly without a thin Web `Request`/`Response` wrapper.
- **Mitigation:** Pin tested Bun versions in CI, isolate Bun-specific APIs inside thin adapter layers (`@bunest/http`), and publish a Bun version support matrix.
