# ADR-011: `Bun.serve({ routes })` Native Routes Support Matrix & Controlled Fallback Dispatcher

- **Status:** Accepted
- **Date:** 2026-11-20
- **Related:** [RFC-001](../rfcs/RFC-001-controller-routing.md), [ADR-001](./ADR-001.md), [ADR-006](./ADR-006.md), [ADR-008](./ADR-008.md)

## Context

`Bun.serve({ routes, fetch, websocket })` provides an ultra-fast native Zig router, but it does not implement every HTTP framework feature out of the box. Empirical runtime probes against **Bun 1.4.3** reveal exact capabilities and gaps that `@bunest/http` must handle cleanly without sacrificing native fast-path performance for common routes.

## Decision

### 1. Empirical `Bun.serve({ routes })` Support Matrix (Verified on Bun 1.4.3)

Supported native `routes` values in Bun 1.4.3: single function handler `(req: BunRequest<Path>, server) => Response`, per-method map `Partial<Record<"GET"|"POST"|"PUT"|"DELETE"|"PATCH"|"HEAD"|"OPTIONS", Handler | Response>>`, static `Response` (reusable across requests, matches all methods), `false` (fall through to `fetch`), `BunFile`, `HTMLBundle`, and `{ dir, statCache? }` (for `/*` static directories). Native matching precedence is strictly **`static > :param > * > fetch`**.

| Routing Feature                                              | Bun 1.4.3 Native `routes` Behavior                                                                                                                         | Bunest Strategy                                                                                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Static paths (`/`, `/users`, `/api/health`)                  | **Supported natively**                                                                                                                                     | Compile into `Bun.serve({ routes })`                                                                                                  |
| Named path params (`/users/:id`, `/users/:id/posts/:postId`) | **Supported natively**; `req.params` populated & URL-decoded (`%20` -> `" "`)                                                                              | Compile into `Bun.serve({ routes })`                                                                                                  |
| Trailing catch-all wildcard (`/files/*`, `/:org/files/*`)    | **Supported natively** (`/api/*` matches `/api/` and `/api/a/b`, **misses bare `/api`**; `req.params` contains named params only, NOT wildcard suffix)     | Compile into `Bun.serve({ routes })`                                                                                                  |
| Per-path function handler vs per-method object               | Both **supported natively**; `{ GET }` auto-handles `HEAD` (invokes `GET` handler with `req.method === "HEAD"` and strips body; explicit `HEAD` overrides) | Register a **single per-path compiled dispatcher closure** in `routes[path]` (see §2)                                                 |
| Native `req.cookies` (`CookieMap`) & `server.requestIP(req)` | **Supported natively** on `BunRequest` / `Server`                                                                                                          | Used by `@Cookies()` and `@Ip()` parameter extractors ([ADR-004](./ADR-004.md))                                                       |
| WebSocket upgrade (`server.upgrade(req, { data, headers })`) | **Supported natively** from both `routes` handlers and `fetch()` (return `undefined` on success)                                                           | Dispatch WS gateway upgrades from `routes` or `fetch()`                                                                               |
| Static `Response` / `BunFile` / `{ dir }` shortcuts          | **Supported natively** (matches all methods)                                                                                                               | Reserved for static-asset optimization (not controller routes with middleware/guards)                                                 |
| **Unmatched HTTP method -> `405` + `Allow` header**          | **NOT native** — `{ GET, POST }` receiving `DELETE`/`OPTIONS` falls through to `fetch()` (or returns empty `404` with `Allow: null` if `fetch` omitted)    | Handled directly in **O(1)** inside each path's compiled `routes[path]` dispatcher (and in Fallback Radix Router for advanced routes) |
| **CORS preflight `OPTIONS`**                                 | Unmatched `OPTIONS` falls through to `fetch()`                                                                                                             | Handled directly inside per-path `routes[path]` dispatcher (with exact allowed methods) AND in `fetch()` fallback                     |
| **Trailing slash (`/users/` vs `/users`)**                   | **NOT native** — `/users/` misses `/users` and falls through to `fetch()`                                                                                  | Strict match by default; opt-in `ignoreTrailingSlash: true` handled in `fetch()` fallback                                             |
| **Mid-path wildcard (`/files/*/meta`)**                      | **NOT native** — falls through to `fetch()`                                                                                                                | Compiled into **Fallback Radix Router**                                                                                               |
| **Optional params (`/users/:id?`)**                          | **NOT native** — treated literally as param key `"id?"`                                                                                                    | Compiled into **Fallback Radix Router**                                                                                               |
| **Regex-constrained params (`/users/:id(\\d+)`)**            | **NOT native** — treated literally as param key `"id(\\d+)"`                                                                                               | Compiled into **Fallback Radix Router**                                                                                               |
| **Host-constrained routes (`@Controller({ host })`)**        | **NOT native**                                                                                                                                             | Compiled into **Fallback Radix Router**                                                                                               |
| **`@All()` combined with specific routes**                   | Needs deterministic precedence (specific verb overrides `@All()`)                                                                                          | Handled cleanly inside per-path `routes[path]` dispatcher (`methods[method] ?? allHandler`)                                           |

### 2. Hybrid Route Compilation Strategy (Bootstrap)

At bootstrap, `@bunest/http`'s `RouteCompiler` classifies every normalized `RouteDefinition`:

1. **Canonical duplicate detection (all routes):**
   - Canonicalize parameter names to positional placeholders (`/users/:id` and `/users/:userId` -> `/users/:_`).
   - Duplicate `(method, canonicalPath, host)` MUST throw `DuplicateRouteException` before `Bun.serve()` starts.
2. **Native-eligible classification & Per-Path Compiled Dispatcher (`routes[path]`):**
   A path group compiles directly into `Bun.serve({ routes })` when ALL routes on that canonical path satisfy:
   - No `host` constraint on their `@Controller()`
   - Path contains only static segments, simple `:param` segments (matching `/^:[A-Za-z_][A-Za-z0-9_]*$/`), and/or a single trailing `/*` wildcard
   - Not shadowed by a fallback-only route on the same path pattern (e.g., if the same path has a host-constrained sibling, route that path through the fallback router so host discrimination works deterministically)

   **Why a single per-path compiled dispatcher closure `(req, server) => ...` in `routes[path]` instead of a raw `{ GET, POST }` map:**
   - Preserves Bun's native Zig radix router, `req.params`, `req.cookies`, and `static > :param > * > fetch` precedence.
   - Dispatches `methods[req.method]` in **O(1)** (mapping `HEAD` to `GET` with empty body when no explicit `HEAD` route exists, and falling back to `@All()` handler if registered).
   - Handles **CORS `OPTIONS` preflight** immediately on matched paths without falling through to `fetch()`.
   - Returns **`405 Method Not Allowed` with precomputed `Allow` header** (e.g., `"GET, HEAD, POST"`) directly on matched paths without re-matching the URL in `fetch()`, routing through Global Exception Filters and preserving CORS headers!
   - Executes pre-bound global + module `MiddlewareConsumer` chains resolved at bootstrap—zero per-request middleware path matching on the native hot path.

3. **Fallback Radix Router (advanced routes):**
   - Routes with `host` constraints, mid-path wildcards, optional params, or regex-constrained params compile into `@bunest/http`'s lightweight Fallback Radix Router, which runs the exact same `CompiledExecutionPlan` closure and emits `405` + `Allow` on method mismatch.

### 3. Controlled Fallback `fetch(req, server)` Dispatcher Order

Any request not matched by `Bun.serve({ routes })` enters Bunest's `fetch(req, server)` handler in exact order:

```text
fetch(req, server)
  1. WebSocket Upgrade Check (if WS gateway registered on pathname -> server.upgrade(req))
  2. Trailing-Slash Normalization (ONLY if BunestApplicationOptions.ignoreTrailingSlash === true
     and pathname !== "/" && pathname.endsWith("/"):
     strip trailing "/" and re-dispatch against compiled native path table or fallback router)
  3. Fallback Radix Router Match (host-constrained, mid-path wildcards, optional/regex params):
     -> if path matches & method matches: run compiled route closure (full ADR-008 pipeline)
     -> if path matches & CORS preflight OPTIONS: return 204 with CORS headers
     -> if path matches & method mismatches: throw MethodNotAllowedException (405) + sorted Allow header
        through Global Exception Filters + CORS headers
  4. Unmatched CORS Preflight Check (if CORS enabled && req.method === "OPTIONS" && Origin + ACRM headers):
     -> return configured preflight response (204) or 404 per CorsOptions
  5. 404 Not Found:
     -> throw NotFoundException(`Cannot ${req.method} ${pathname}`) through Global Exception Filters
        (with CORS headers applied)
```

### 4. Ephemeral Port & Testability

`@bunest/http` MUST support `port: 0` (ephemeral OS-assigned port) in `app.listen(0)` and expose `app.getUrl()` / `server.port` / `server.url`, enabling conflict-free parallel E2E tests in `bun:test`.

## Consequences

- **Positive:** 95%+ of REST routes run at native `Bun.serve({ routes })` Zig routing speed with zero reflection and pre-bound middleware; 405 + `Allow`, CORS preflight, custom 404 exception filters, host constraints, and complex wildcards work reliably without hacking around Bun limitations.
- **Negative:** Maintaining both native route compilation and a lightweight fallback radix router adds modest code in `@bunest/http`.
- **Mitigation:** Both paths execute the exact same `CompiledExecutionPlan` closure ([ADR-008](./ADR-008.md)), guaranteeing identical middleware/guards/pipes/interceptors/filters/serialization behavior regardless of which matcher matched the request.
